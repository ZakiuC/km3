## 一、A —— 退出/中止时必须安全关停（**安全缺口，最高优先**）

### 现状（已核实）

`pmp4010_tui.py` 的退出路径：

```python
def _quit(self):
    ...
    self.controller.close()      # 只关总线
    return True
```

`run()` 的 `finally` 里也是 `self.controller.close()`。
`BenchController.close()`（约 423 行）**只做 `self.bus.close()`，不失能**。

**后果**：操作者按下 `E` 使能后直接退出，电机**带着力矩留在使能态**，
总线一关就再也没人管它。台架上是单台空载，看起来无害；装机后是带着负载保持。

### 要做的

退出前必须先**失能并确认**，再做别的。顺序不能反：

1. 对**本会话里曾经被使能过的节点**发失能（`6040h = 0x06`，即 Shutdown），
   然后读回 `6041h`，要求 `operation enabled` 位为 0
2. **读回确认不了**（超时 / 隔离 / 状态字读不到）时
   —— **不得静默通过**，必须打印「节点 N 失能未确认，状态未知，须独立急停」
3. 关总线

### 必须遵守

- **不新增接口名**：复用 `execute()` 里已有的 `session.stop_after_failure()` /
  `session.disable()` 路径，不要另写一套发帧逻辑
- **已隔离的节点不得重试**。`SdoClient` 超时后 `quarantined` 是不可自愈的；
  对隔离节点只打印状态，不发帧
- 退出时**如果正在执行动作**，先走已有的「中止 → 失能 → 确认」流程
  （`_quit()` 现在就是这么做的），只在**动作结束之后**才允许真正关总线
- 关停失败**不得阻止退出**（否则用户按 Ctrl+C 卡死），但**必须以退出码或终端文本
  如实报告未确认**

### km2 的注释值得抄（但结论不一定适用）

`motor_test.cpp:905` 上方写着：不要在关停时存位置，因为电机可能已断电或计数器被清零，
会把错误值写进文件覆盖正确记录。

**km3 没有位置文件**（PMP4010 自己回零，`6098h=35`），所以这条**不适用**。
但**同一个道理**在这轮适用：退出时的清理动作，必须只做「把系统带回更安全状态」的事
（失能），**不做**会写入或改变持久状态的事。**退出路径里不得写任何电机参数。**

## 二、B —— 把将要写出去的原值显示出来

### km2 的做法

```cpp
cmd.speed_001dps = static_cast<int32_t>(rpm * MOTOR_SPEED_RPM_TO_DPS / MOTOR_SPEED_CTRL_SCALE);
std::cout << "  换算: " << rpm << " RPM → raw=" << cmd.speed_001dps << "\n";
```

用户输入 RPM，发出去是 raw，中间这个换算**必须显示**。
验收时对不上，才能分清是换算错还是驱动错。

### km3 现状

`BenchController.review()` 的 `lines` 里有：

```
目标 -1414 U = -3.884度 电机轴；相对当前位置 +50 U / +0.137度
```

有用户单位和角度，**没有实际写进对象字典的整数值**。

### 要做的

审阅行里补上**实际会写出去的对象与值**，形如：

```
写 607Ah = -1414（int32，用户单位）
```

要求：

- **值必须是真正会被写出去的那个整数**，不是重新算一遍的近似
  —— 最好直接从 `_args()` 之后构造出的写入计划里取，而不是在显示处再算一次
- 同时标出**对象索引和数据类型**（`607Ah int32` / `60FFh int32`），协议事实用英文（规则 8）
- 速度类对象（`60FFh`）现在不会写（换算链未实现），但**显示格式要预留**，
  下一轮放开时直接能用
- **设零点**不写 `607Ah`，它写的是 `6040h`；这种情况下显示 `写 6040h = 0x001F（触发回零）`
  之类，**不要编一个不存在的坐标写入**

## 三、C —— 批量失能 / 批量快停（**只做这两个，不做批量运动**）

### km2 的做法

`multi_motor()` 支持：`0` = 全部在线电机；逗号或空格分隔多个编号；
**去重**；**无效编号明说「忽略无效编号: N」**；目标数为 0 时明确提示（全部模式下提示「请先扫描」）。

### km3 要做的

主界面（`overview`）上加**两个**批量动作：

- **全部失能**
- **全部快停**

### 必须遵守

- **不做批量位置运动**。4 台同时动的每一台都要独立的起点、行程、1° 硬顶、
  `check_start` / `check_envelope`，收益与风险不成比例。**本轮明确不做。**
- 批量动作作用于**当前在线且未被隔离**的节点；离线/隔离的**列出来说明跳过**，
  不静默略过
- **至少作用 1 台**才允许执行；0 台时明确提示「无在线节点」
- 仍然走**两段确认**，确认串里必须含动作名与节点列表，
  例如 `DISABLE ALL 1,3`，逼操作者看清动的是哪几台
- 执行结果**逐台**报告（成功/失败/状态未知），不能只给一个总结论

## 四、D —— 把「要不要确认」收敛成一个判据

### km2 的做法

```cpp
if (!is_read && cmd_sel != 11 && cmd_sel != 15 && !confirm("  确认发送?")) return;
```

一行判据覆盖所有命令。粗糙，但**不会漏**。

### km3 现状

`begin_action()`（约 191 行）里判断：
- 有没有 OD 会话确认串
- 有没有填过行程/预算
- `action not in ('disable', 'stop')`

`review_action()` 里再走一遍 `review()` → `confirm` 视图。
判断散在两处，新增动作时容易只改一处。

### 要做的

把「这个动作是否需要两段确认」收敛成**一个函数/一张表**，
`begin_action()` 和 `review_action()` 都从它取，不再各自写 `if action in (...)`。

要求：

- 判据**必须是数据**（例如 `ACTIONS` 表里加一列），不是散落的 `if`
- **只读动作**（扫描、刷新、进详情、翻帮助）不确认 —— 保持现在的手感
- **写入类动作**（使能/失能/快停/绝对/相对/设零点）全部确认 —— **不得因为收敛而放松**
- 收敛后 `_test_bench.py` 里**每一个现有守卫用例必须仍然通过**；
  如果某个用例因为收敛而失效，那是收敛做错了，不是用例过时了

## 九、容易踩的坑

1. **退出关停 ≠ 快停**。快停是 `6040h` 的 Quick stop 位，失能是 `0x06`。
   退出用**失能**，不要用快停。
2. **隔离的 `SdoClient` 不可自愈**。对它发帧只会再超时一次。
3. **关停失败不能把退出卡死**，但必须如实报告。
4. **`run()` 的 `finally` 是真实 SIGINT 也会走的路径**，在那里做的清理必须是安全的。
5. **批量动作的确认串必须含节点列表**，否则操作者不知道动的是哪几台。
6. **收敛确认判据时最容易犯的错是"顺手放松"** —— 比如把使能也算成只读。
7. **报数报实测** —— 本项目出过"说全绿但两个闸门是红的"。
