### 禁读目录约束与检查环境

请求同时要求“不读/改/删”受保护目录和执行该目录的列举命令，二者冲突；本轮遵守前者，跳过后者，不能声称通过列举确认其为空。未执行对应 `ls` 或 `git ls-files`。

文档检查脚本原有三个 `find .` 虽用过滤谓词排除受保护目录结果，仍会遍历其内容。未修改检查器；运行时给 PATH 加临时 `find` 包装，将根目录遍历替换为先 `-prune` 该目录再执行原谓词。文档闸门结果对应上表所列带 PATH 的实际命令，不代表无包装环境的原始遍历。包装只排除请求禁止读取的目录，不增加任何源码或手册引用豁免：

```bash
#!/usr/bin/env bash
if [[ "$1" == "." ]]; then
  shift
  exec /usr/bin/find . -path './harness' -prune -o \( "$@" \) -print
fi
exec /usr/bin/find "$@"
```

## 修复细节与测试语义

- A1：位置写入公共路径读取 OD 生成条目的软件限位上下界，拒绝反转限位、越界、读取超时或中止；覆盖 typed API、通用 WriteObject、SdoWrite，不能从原始写入绕开。边界值包含上下限。速度的用户单位/s 到 rpm 换算链尚未接通，所以所有速度目标显式返回 EInvalidConfig，不猜测系数，也不发送读取或写入帧。
- A2：CiA 402 控制字的公共写入口要求模式选择器为 0；普通状态读取不增加模式选择器事务。Python 对 enable/disable/stop/home 及每一次控制字写入均重新检查选择器。非 0、超时和中止拒绝后续控制字写入。
- A3：三个字符串身份对象进入 OD 生成台账，标为已核对并引用 E06 表10-5。未知对象必须拒绝；定宽对象严格匹配长度，可变字符串按共享 SDO 容量 256 字节检查。该上限是实现容量，并非厂家声明的字符串长度。台账新增软件限位上界及三个字符串后，共 83 条、77 条已核对、6 条未核对；既有六条未核对不改变。
- B1：回零 bit10、bit12、bit13 及控制字/状态掩码来自共享 JSON 生成物；出处写入共享定义说明，驱动与 Python 使用同一常量源。
- B2：C++ 使用共享加急应答掩码，与 Python 对齐；共享 golden 数据覆盖五个分歧字节，另有全部 256 个命令字的枚举回归。
- B3：Python 分段上传同时受 256 字节容量、有限段数和事务总期限限制；持续非末段响应报明确错误，不静默截断；容量边界、超容量、异常切换位和声明长度均有回归。
- B4：已发 SDO 事务超时后隔离该节点；后续同节点 SDO 返回 EDeviceBusy，既不发送，也不消费迟到回复。独立节点仍可使用。只有调用者确认外部运输层与从站已恢复、旧回复不再可能到达，才能显式确认恢复后读取新值。

A1/A2 的“零帧”在先读再判定的要求下需区分：必要的限位/选择器 SDO 读取本身会发帧；回归断言的是拒绝时运动写入帧数为零。全局 OD 未准入、未知对象、速度换算未配置等能预先判定的情况，断言总发送帧数为零。不能把“零运动帧”误写成“总线零帧”。

B4 与请求中“下一次读自动取到新值”存在有意的行为差异：CANopen SDO 响应没有事务序号，单纯清队列不能区分之后才到达的旧响应与当前请求响应。实测验证隔离后迟到旧值不会被采用，并在 fixture 模拟独立外部恢复后获得新值；不宣称能在未知运输延迟下自动安全重试。超时后的同节点 SDO 安全清理也会被隔离阻止，需要独立安全控制；本轮未执行任何外部恢复或硬件操作。

C1 的 Python NMT 准入顺序已统一为 OD→标准层→RT，新增顺序测试；C4 显式窄化与 C5 更严格回零合取判据注释已处理。C2 尚未接通的配置字段、C3 实际速度单位选择器仍为后续工作，本轮不宣称已实现单位换算。
