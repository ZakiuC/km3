# 立迈胜 PMM/PMMP CANopen 伺服控制代码

这套代码根据你提供的两份 PDF、旧 `mvd_motor.cpp`、NiMStudio PDO 配置及参数数据库编写。实际总线接口沿用旧代码的 **Linux SocketCAN**，使用 C++17。支持 CiA402 轮廓位置 PP 和轮廓速度 PV；代码可直接编译，电机运行结果仍需在你的硬件上验证。

**当前实机程序不能在 Windows 下控制 USB-CAN。** NiMStudio 能连接电机说明硬件通信正常，但它不等于 SocketCAN 接口。如果实际运行端是 Windows，需要提供 USB-CAN 型号及对应 SDK，用本项目的 `CanBus` 接口替换 `socketcan.hpp`；CANopen 控制部分可以复用。Windows 可以编译运行这里的离线协议测试。

## 文件与编译

| 文件 | 用途 |
|---|---|
| `pmm_canopen.cpp` | 交互程序入口 |
| `canopen_servo.hpp` | CANopen SDO、CiA402 状态机、位置与速度控制类 |
| `socketcan.hpp` | Linux SocketCAN 通信实现 |
| `protocol_tests.cpp` | 不接电机的协议测试 |
| `CMakeLists.txt` | 可选 CMake 构建 |

将源码压缩包解压到 Linux 上，在解压后的目录运行：

```bash
g++ -std=c++17 -O2 -Wall -Wextra -Wpedantic pmm_canopen.cpp -o pmm_canopen -pthread
```

也可以用 CMake：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
ctest --test-dir build --output-on-failure
./build/pmm_canopen can0 1
```

需要 Linux 的 C++17 编译器、Linux CAN 头文件及 SocketCAN 可识别的适配器；无需 CANopen 第三方库。串口形式的 USB-CAN、厂家私有 USB 驱动不会自动成为 `can0`。

## 通信设置

NiMStudio 参数数据库中的默认节点是 **1**；波特率参数 `200C:03=8` 对应 **1 Mbps**。这只是默认值，数据库的 `CurValue` 也不是本次电机实时读取结果。如果你在上位机中改过节点或波特率，以下命令必须用实际值。

先结束 NiMStudio 对这台电机的控制，保证同一节点只有本程序发控制命令。CAN 接线保留你已测试成功的连接。

对于已存在的 `can0` 接口，设置 1 Mbps：

```bash
sudo ip link set can0 down
sudo ip link set can0 type can bitrate 1000000
sudo ip link set can0 up
ip -details -statistics link show can0
./pmm_canopen can0 1
```

程序不会配置适配器波特率，也不会自动改电机的 `200C:02/03`、PDO 映射、电子齿轮、软件限位或编码器零点。只有明确执行 `id` 命令才修改节点并保存。使用经典 CAN 标准帧，不使用 CAN FD。节点范围 1..127，NMT 只发送给选定节点。

PMMP 手册 3.3.2 / 表 3-8（PDF 第 21 页，印刷第 14 页）标注 X2/X3 的 CAN 引脚：1=GND、2=CANL、3=CANH、4=GND；插头方向以手册图示为准。4.4.4 要求链式总线、参考地连接及两端匹配电阻。你已经验证接线时可沿用原连接。

## 第一次位置控制

启动程序只连接总线，不使能、不发运动目标。首次测试请让电机能够自由转动，并确认所需运动空间；有重力负载时要先承托，因为 `disable` 和程序退出会失去保持转矩。

逐行输入下面的命令，不要整段一次粘贴到未验证的电机：

```text
status
pp 360 360
enable
rel 10 20 10
status
halt
disable
quit
```

含义：读取状态，配置 PP 模式与 360°/s² 加减速度，使能，从当前实际位置正向移动 10°，运动速度 20°/s，最多等待 10 秒。到达后保持位置；`halt` 保持使能，`disable` 随后失能。

`rel` 的角度和速度都是输出轴单位。如果电机没有外置减速器，输出轴就是电机轴。程序默认机械减速比 1；比如外置减速器为 36:1，启动时传入：

```bash
./pmm_canopen can0 1 36
```

这里的 36 表示实际机械减速比；它与驱动器的电子齿轮 `6091` 是两个不同参数。程序同时考虑两者，并不会将旧关节电机的减速比自动套用到新电机。

## 常用命令

| 命令 | 含义 |
|---|---|
| `status` | 读取状态字、模式、错误码、位置、速度、换算参数、软件限位；并尝试读取电压、温度、转矩 |
| `pp` 或 `pp 360 360` | 配置 PP；可给出输出轴加速度、减速度，单位 °/s²；保持失能 |
| `pv` 或 `pv 360 360` | 配置 PV；切换前必须先失能 |
| `enable` | 按 0x06 → 0x07 → 0x0F 状态机使能；PV 先清零速度目标，PP 先设置当前位置 |
| `abs 90 20 10` | 输出轴绝对位置 90°，速度 20°/s，等待上限 10 秒 |
| `rel -10 20 10` | 从采样时的实际位置反向移动 10° |
| `rpm 60 5` | **电机轴**转速 +60 rpm，运行 5 秒后暂停停机 |
| `rpm -60 5` | 电机轴反转 -60 rpm，运行 5 秒后暂停停机 |
| `halt` | 按 6084 的减速度停下并保持使能；速度模式同时清零目标 |
| `disable` | 先暂停停机，再失能；失去保持转矩 |
| `quickstop` | 写 6040=0x0002；按 6085 停机，随后自由运行 |
| `reset` | 明确请求故障复位；不会自动反复清故障 |
| `id 2` | 电机失能时，将节点改为 2，保存全部当前参数并退出；重新上电后生效 |
| `help` / `quit` | 帮助 / 退出时尝试暂停停机、失能 |

位置命令默认等待上限 30 秒；速度命令默认运行 5 秒。运动命令执行期间不能输入新命令中断它，可以按 Ctrl+C 请求停机并退出。等待输入时，每约 200 ms 读取一次状态字；不另开 CAN 收发线程。

位置模式的 `abs` 使用驱动器现有坐标系，**程序启动位置不是新的零点**。没有做机械零点校准时，优先用小幅 `rel` 测试。`rel` 在代码中读取 `6064`，加位移后发绝对命令，因此不受 `60F2` 的原有相对位置基准选择影响。

速度模式测试顺序：

```text
disable
pv 360 360
enable
rpm 60 5
disable
```

故障复位需要先处理电机报警的实际原因，然后执行 `reset`，重新 `pp` 或 `pv`、`enable`。快速停机后可执行 `disable`、重新配置模式、使能。程序检测到 SDO 超时、驱动器重启或 EMCY 异常后退出；重新建立连接前不要自动重发上一条运动命令。

## 协议与单位

旧代码的 `0x140+ID`、`0xA4`、`0x92`、`0x8C` 是旧电机的私有协议，不能沿用到新电机。这里使用：

| 项目 | 本程序实现 |
|---|---|
| SDO 请求 / 响应 | 0x600+节点 / 0x580+节点；小端；DLC=8 |
| 写入命令符 | 1 字节 0x2F，2 字节 0x2B，4 字节 0x23 |
| 读取 / 写成功 / 异常 | 0x40 / 0x60 / 0x80；响应同时匹配索引、子索引和节点 |
| CiA402 模式 | `2002:01` 写 uint16 的 0；`6060` 写 int8 的 1（PP）或 3（PV） |
| 状态机 | 写 6040 后读取 6041，按掩码检查 Ready、Switched on、Operation enabled |
| PP 目标 | 607A=int32，6081=uint32；6040：0x2F → 0x3F → 0x2F，等待 bit12 握手 |
| 到达判断 | 状态字 bit10，同时检查 6064 实际位置进入 6067 窗口，防止旧到达位造成误判 |
| PV 目标 | 60FF=int32，单位 **用户单位/s**，不是直接填 rpm |
| 暂停 / 快停 | 配置会话中的 605D=1、605A=2；不保存到 Flash |
| 反馈 | 6064 位置；606C 速度，读取 2006:12 判断是 rpm 还是用户单位/s |

程序每次模式配置都读取：

```text
R = 608F:01 / 608F:02                    编码器增量/电机圈
G = 6091:01 / 6091:02                    电子传动比
M = 命令行传入的机械减速比               电机圈/输出轴圈
U = R × M / G                            每输出轴一圈的用户单位

目标位置UU  = round(输出角度 × U / 360)
轮廓速度UU/s = round(输出角速度 × U / 360)
PV目标UU/s  = round(电机rpm × R / (60 × G))
```

手册默认 R=10000、G=1，没有机械减速时：360°=10000 UU，90°=2500 UU，300 rpm 对应 60FF=50000。驱动器若已修改过单位参数，则以实际读取值计算。

程序检查数值范围、NaN/无穷、非正轮廓速度、607D 软件限位、607F 最大轮廓速度、60C5/60C6 最大加减速度，并保留现有限位。数据库中的默认 607D 范围为 -65535..65535 UU，不能假设任意多圈目标都被允许。用户还应按实际机构设置自己的运动边界。

本程序在 `pp` / `pv` 配置时改变以下运行参数：2002:01、6060、6083、6084、605D、605A；PP 另写 607A 和 6082=0，PV 另写 60FF=0。普通运动操作不调用 1010 保存参数，不恢复出厂，不清编码器。`id` 是明确的持久修改操作，会调用 1010:01 保存**全部当前参数**，因此此前运行时修改过的加减速度等也可能一同保存；只改 ID 时，最好在运动配置前执行。

配置模式时会读取通信看门狗 `200C:1B`。如果它大于零，按照手册 7.10，通过定期向该对象写回同一个时间值喂狗；不会关闭看门狗或更改时间值。读取状态不等于喂狗。本程序按现有时间值约三分之一的间隔喂狗，并要求启用时的时间值至少 1000 ms，较短周期需要另写实时通信调度。旧固件若不存在该对象则跳过。只读会话不主动接管看门狗；程序退出后不再喂狗，驱动器若保持看门狗开启，可能按原设置报告通信报警。自定义集成时也应定期调用 `pollHealth()`，并根据现场需要配置通信故障响应。

抱闸不使用旧电机的 0x8C 命令。带抱闸的型号沿用驱动器原有配置和使能/失能时序；软件 `halt` 是电机保持转矩，不是明确的机械抱闸指令。本项目没有自动回零、力矩控制、CSP 或多轴同步控制。

## 集成到你自己的 C++ 项目

交互程序以外可以直接使用头文件：

```cpp
#include "socketcan.hpp"

int main() {
    nimotion::SocketCan bus("can0");
    nimotion::Servo motor(bus, 1, 1.0); // 节点1，无机械减速
    motor.configure(1, 360, 360);      // PP，角加速度/减速度
    motor.enable();
    motor.moveRelative(10, 20, 10000); // +10°，20°/s，最多等10秒
    motor.halt();
    motor.disable();
}
```

类不是线程安全的，同一节点不能由多个 SDO 客户端同时控制。运动函数是阻塞式的；用于多轴同步或高频轨迹时，应另外实现 PDO/SYNC 和调度。本示例只提供单台电机的基本控制。

## 节点 ID、多圈记忆和最大转速补充

### 修改节点 ID

CANopen 的 ID 为 1..127，默认 1；同一总线上每台电机唯一。NiMStudio 参数名称为“驱动器轴地址”，对象 `200C:02`（uint16），修改后执行参数保存，再将电机断电重新上电，按新 ID 连接。不要把通用参数数据库中同时覆盖其他协议的 0..247 地址范围当成 CANopen 节点范围。

新代码示例：先以旧 ID 连接，输入 `disable`、`id 2`。程序确认保存后退出。电机断电重新上电，再运行 `./pmm_canopen can0 2`。`id` 只写入新地址，不让电机重启；旧会话的 CAN ID 不会立即切到新地址。

旧 ID=1，新 ID=2 的原始 SDO：

```text
CAN-ID 0x601, DLC 8: 2B 0C 20 02 02 00 00 00
CAN-ID 0x601, DLC 8: 23 10 10 01 73 61 76 65
```

分别为写 200C:02=2，以及 1010:01 写 0x65766173（save）保存全部当前参数。先确认每次写入的成功应答；不要在使能运行时保存参数。

### 多圈记忆

PMMP 产品说明书表 3-1（印刷第 8 页）给出 17 位绝对值多圈编码器、多圈位置范围 -2147483648..2147483647，外置 3.6V 电池，但未给出多圈圈数位数或明确的最大掉电记忆圈数。不能将这个“位置范围”直接称为 21 亿圈，也不能将“17 位”直接当成多圈圈数位数。

CANopen 的 6063/6064/607A 为 int32。按 608F=10000/1、6091=1/1 的默认单位，通信坐标的数值范围约为电机轴 ±214748.36 圈；这只是通信位置数值的换算，并不证明编码器硬件能够掉电记忆相同圈数。607D 默认 ±65535 UU 对应约 ±6.5535 圈，是另一个软件限位。

确认掉电多圈能力需要完整型号的编码器字段：D 选项为 17 位多圈；B 选项依具体机型为单圈绝对值或增量型。多圈绝对恢复模式为 2005:18=0，外接电池需有效。最终圈数容量须由具体编码器规格或厂家确认。

### 转速

PMMP4010 系列手册图 2-5 / 图 2-6：D03 为 48V，D04 为 24V；额定转速 3000 rpm，矩频曲线延伸至 3600 rpm，并在该端点降至零转矩。3600 rpm 是曲线的端点，不能当成有负载时可持续使用的转速保证。超过额定转速后的可用转矩下降，实际还取决于型号、供电、负载及限速设置。

通用对象字典的默认值有 2000:0F=6000 rpm、6080=4000 rpm、2006:0A/0B=4000 rpm；这些不是每种 PMMP 电机的最高转速承诺。默认 607F=500000 UU/s 在 R=10000、G=1 时对应 3000 rpm，本程序按该值限制 PP/PV 目标。`status` 已增加这些参数的读取输出。勿为追求 6000 rpm 直接放大限速参数；先核对完整型号与矩频曲线。
