## 2. 使用入口和实际界面

```sh
python3 -I device/drivers/pmp4010/tools/pmp4010.py
```

菜单为 Status / Calibrate / Position / Params / Raw frames。Up/Down 或 j/k 选择，Enter 进入；表单 Enter 开始编辑、再次 Enter 提交字段，Esc 先取消草稿，再按 Esc 返回菜单；选中菜单项与字段焦点保留。q 在编辑态只是输入字符。F5 先审阅，再填写确认字段，提交字段后再次按 F5 才执行。Enter 不会发起运动或写参数。

Status 从 `panel_rows()` 生成只读快照，不开总线。Calibrate 填 node、apply=yes 后由 F5 审阅/确认读取；Position 的 F6 可在目标、位移等尚未填写前读取标定和起点，也必须确认。普通 CLI `--calibrate --apply` 仍只读四项；TUI 起点快照读取四项标定加实际位置，共五项上传。

Position 表单包含全部要求的九项及节点、apply、旁路理由、RT 确认、离线标定/起点/上限字段；较小窗口滚动显示字段。Params 的 action 支持 backup/interpolation/transmission/rollback/save，set 接受同 CLI 的对象覆盖表达式。Raw frames 按 F5 开始纯接收，Esc 停止，PgUp/PgDn 翻阅日志。

## 3. 八条设计准则落实

1. **重复动作**：菜单和同一日志区支持看状态→读标定→填表/改参数→F5 审阅→明确执行→看结果；较小屏幕的表单和日志可滚动。
2. **确认强度**：RAM 批次为一次 `WRITE <iface> <node>`；回滚为明确 `ROLLBACK ...`；真实运动为 `MOVE <iface> <node> <target>`；EEPROM 独立 save 先 `PERSIST ...`，再手工构造 `SAVE <iface> <node> <decimal serial>`，两次都需要 F5。页面明确 PERSIST TO DEVICE EEPROM / cannot undo / no retry；错误确认零执行，不自动 save。
3. **状态、输入、渲染分离**：Field 保留 committed/draft，build/preview 只消费内存；poll 调度单一工作线程并处理事件，文件、状态查询和总线 I/O 都在工作线程。三种尺寸下对 build 注入“任何 I/O 即失败”的测试成立。
4. **编辑焦点优先**：dispatch_key 先处理表单编辑，q/j// 都属于内容；忙时冻结字段编辑，Esc 请求取消、q 请求取消后退出，等待清理，不能在事务中开另一个控制主体。PTY 实测 qj/ 输入、取消草稿、返回/重进和焦点保留。
5. **取消与回滚事实分离**：共用事务上报 no_writes / restored_confirmed / unknown；只有逐项恢复写读确认才显示 RAM restored。失能确认、机械状态分别显示，离线结果明确 OFFLINE simulated、device UNKNOWN。日志有失败对象及期望值；隔离后不建新客户端冒充恢复，同一 iface/node 锁定后续真实 SDO，修改位速率也不能绕过；重启工具不构成外部恢复证明。
6. **终端恢复**：curses.wrapper 加 finally 恢复光标与原 SIGWINCH；真实 SIGINT 后等待同一客户端的有界清理，退出备用屏幕后再打印最终状态。PTY 比较完整 termios，另测 echo 和光标，覆盖正常、Ctrl-C、字段内 Ctrl-C、poll/build 异常。
7. **80×24 和未知尺寸**：沿用 resolve_size，ioctl=0×0 时降级24×80；表单可滚动，精确参数清单保留在可翻页日志。真实 PTY 覆盖0×0/24×80/36×140→24×80；单测另外覆盖退化 Grid。
8. **变化时渲染**：继续用 poll_ms=250；只有字符帧变化才 render。resize 修复保证重复 KEY_RESIZE 不触发再次 resize 和全量绘制。原始 PTY 还检查了多轮空闲轮询不会擦掉首帧；没有固定帧率动画、颜色或鼠标。

UI 文案为英文，保留原 CLI 中文诊断；TUI 以英文摘要及 ASCII JSON 转义诊断保存细节，不向 curses 写双宽中文字形。未引入依赖、颜色或字符属性。PTY 原始流中 curses 初始化/退出的终端模式及复位序列属于终端管理，应用 render 未增加 SGR。

## 4. render / resolve_size 是否改动

**均未改动**，主会话用 AST 提取 HEAD 和当前函数源码比较，逐字符相等；原 test_tui.py 也没有修改。

```text
render source_identical=True sha256=fe029aedfacab9221ba71bcd012fcfbb64b4d44bd66eb24014ea48c7b061e2ed
resolve_size source_identical=True sha256=6e9570f80f07568307d1ee8e0b03ea9f27d16fd674cc891e702c3347211a1dff
```

改动在其上下游：表单画字符光标 `_`；主循环先消化 curses 自身的 refresh，再使用原 render；尺寸实际变化才调用一次 resize API，避免它自己生成 KEY_RESIZE 形成循环。
