# 独立 C++ 手动测试：最终本地验收与交付

本轮交付是基于原示例 SocketCAN/Servo 基础层的独立 PP 手动直线测试工具，正式 driver 暂不迁移。
全部验收在开发机完成；未访问真实 CAN、SSH、板端、部署或运动现场，未提交代码。

## 保留的失败、修复与限制

1. 原示例两架构编译保留 `protocol_tests.cpp:58` signedness warning；示例源码未改。新工具最终宿主/ASan/TSan/ARM 编译 stderr 均无 warning。
2. `final-asan-ctest` 曾 rc8：旧保护锁 fixture 通过 ACK 等待制造锁，插桩时撞上 SDO 总期限；保留完整输出。fixture 改为 Review→Execute 之间确定性修改 `605D` 产生相同保护锁，再注入 Warning2312 验证不能解锁；没有放宽生产 timeout 或守卫。最终 ASan 53/1004 通过。
3. `final-tsan-pty` 曾 runner rc1、子进程 rc66，报告 double lock/race，原始终端见 [pty-tsan-final/reason.terminal](pty-tsan-final/reason.terminal)。最小对照与本机符号证据确认 GCC11 TSan 缺少 `pthread_cond_clockwait` 拦截，旧 `steady_clock::wait_until` 路径丢失同步关系；不是把未定位的数据竞争当作已修复。四对照为 steady rc66、system rc0、monotonic pthread timedwait rc0、故意去读锁 negative control rc66。详见 [TSan根因与修复](tsan-wait-minimal/根因与修复.md)。所有构建统一使用单调时钟 timedwait，未 suppression、未 no_sanitize、未 sanitizer 特判；最终完整 TSan PTY103 通过。相关 GCC 官方记录由 root 核验：[GCC 官方问题记录](https://gcc.gnu.org/pipermail/gcc-bugs/2022-July/793323.html)。
4. `final`、`final2`、`final3`、`final4` 是过程中保留记录；最终 UI 以 `final5` 为准。backend/preflight 单元通过记录以本报告列出的最终核心 hash 为准。两次源码修复及 UI 日志失败、呈现微调都有新 binary 验证，没有拿修复前通过冒充修复后结果。
5. 依赖闸门 rc0 仍输出 `Python3 ?? 未在映射表中`，不隐藏。它不影响本工具的独立 C++/Threads 构建；本任务未修旧映射表。
6. 初次 OD 递归探查漏掉列表中的 entry 自身，误把 device 嵌套元数据当完整清单，已纠正；权威 `od.json['entries']` 是 5 unverified + 2 assumed，README列出7项。本工具非空人工理由不改变 OD 状态，不证明硬件、抱闸或负载安全。
7. 包 SHA 校验首次人工调用因在 package cwd 下误用仓库相对 recorder 路径而 rc2，尚未启动校验程序；随后正确以仓库 cwd 调 recorder 并在子命令切换 package，rc0。不是被隐藏的测试通过。

- 二进制 SHA256：`758f9107d372622f1104fd2d4972bcb22191f4da6d851913bbcae3ada15a26c2`
- 压缩包 SHA256：`62a92542963d6c5ad9d71b16498e7f98e259762ef3a16204c9c7bfaf78d5f04e`
- 包内含二进制、README、使用说明、完整源码 manifest、ELF_DEPENDENCIES.txt 和 SHA256SUMS。

`readelf` 确认 AArch64，NEEDED 仅 `libm.so.6`、`libc.so.6`、`ld-linux-aarch64.so.1`，最高 glibc 符号 `GLIBC_2.34`。libstdc++/libgcc 静态链接，无 `libstdc++.so.6`、`libgcc_s.so.1` 动态依赖；未现场 load、未确认目标机兼容性。早先动态链接产物要求 `GLIBCXX_3.4.30`，已 superseded，原始报告 `final-arm64-elf.*`、`package-dynamic-superseded/` 和 `.dynamic-superseded.tar.gz` 保留，禁止误当最终包。

README 中基础 ARM 命令是一般动态构建；最终交付以包使用说明及下面的 static 配置命令为准。真机必须显式 `--interface`；通过会话确认页或 `--exclusive-can-ack` 确认其他控制程序已停止。默认 1Mbps、1rpm，SDO timeout 1..500ms；它是 PP 位置入口，不是 PV。链路只检查不修改，实例锁不冒称可证明其他控制程序已停止。未运行真实 pmm_canopen。
