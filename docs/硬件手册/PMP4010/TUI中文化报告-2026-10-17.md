## 二、先确定存储形状，再改变边界语义

`Grid._lines` 仍然是行字符串，无持久化格子数组或占位字符。每行字符数 `len(row)` 可变，
显示列宽始终等于 `Grid.cols`；因此 `_shape()` 同步改为每行 `_display_width(row)` 的元组。
例如 `中文` 与 `ABCD` 都是四列，可以增量比较，不能因字符数不同误判尺寸变化。
宽度规则只实现一次：`tools/hwtui/tui.py::_display_width()` 使用 `unicodedata.east_asian_width`，
W/F 为两列，其余为一列；`pmp4010.py` 仅按需调用这一实现。

差分临时计算每个字形的列跨度，找出新旧两行的共同字形边界，在共同边界之间比较。
变化区间因此一次扩到两帧都安全的边界，并合并相邻区间。旧字与新字错开一列时，
扩张可能穿过多个双宽字到行尾。发出的 CSI 列号为终端列偏移加一，输出内容则按完整字形切片。
`Grid.put()` 的 x、裁剪及推进均按列；覆盖旧双宽字任一半时，另一半补空格，边缘不留下半字。
`Table/Menu/Form`、标题、分隔线、整条提示、Field 字符游标对应的显示列和日志折行都已处理。

### 五条 render 契约

| 原契约 | 结果 |
| --- | --- |
| 1. 空帧/零宽输出空列表 | 保持；新增双宽零尺寸覆盖 |
| 2. None 或形状变化全量重绘 | 保持；形状解释为终端列宽，不再是 Python 字符数 |
| 3. 连续变化列逐区间绝对定位 | ASCII 完全保持；Unicode 为避免半字，扩到新旧共同字形边界，允许连带重画邻近未变列。这是任务 §2.2 所需的明确限定 |
| 4. 每区间独立绝对定位，不追踪终端光标 | 保持 |
| 5. 纯函数，无 I/O，不修改入参 | 保持 |

全量重绘的 ASCII 字节公式不变；Unicode 的 UTF-8 字节数须用 `len(row.encode('utf-8'))`，不能用字符数或列宽替代。

### 既有断言冲突的兼容处理与启动尺寸修复

原 `test_tui.py` 明确断言 `sanitize('电机A') == '??A'`，与新增中文能力存在字面冲突。
按用户明确选择，保持原测试文件中的 61 个用例及断言不动，采用 `sanitize(text, wide=True)` 显式放行可打印双宽字，
所有网格与控件路径均启用；直接调用 `sanitize(text)` 保留旧默认行为。
控制/格式字符所有模式都替换为 `.`，组合标记替换为 `?`，没有放松终端注入防护。
`test_form.py` 中另一条非 ASCII 快照按新的中文显示更新，并仍检查 ESC 不进入网格。
此外，真实 PTY 暴露 ioctl 0×0 + --rows 30 --cols 100 时 curses 仍保留默认 24×80 滚动区域，
使首屏首六行滚出。已在 _main 首次刷新前调用已有 _resize_now 同步两者，
新增启动顺序回归；对应旧 resize 测试的重绘次数由两次调整为一次，仍检查一次 resize 和三次输入读取，避免 resize 事件饿死退出键。
进一步的原始 PTY 字节证明 resizeterm 只改内部尺寸，终端仍保留 CSI 1;24r。
因此 _prepare_screen 在 curses refresh/untouch 后增加 CSI r 重置滚动区域，位于会话初始化/resize 路径，不加入 render 输出。
第二次零尺寸探针确认完整首屏与帮助正常后，再执行全部 PTY 复验。

## 六、帮助菜单完整文案

帮助正文保存在一份 `HELP` 数据清单；五视图用途由同一清单生成。上下文正文用独立 `LogView` 滚动，
四条安全提示在正常尺寸下固定显示。`?`/F1 进入；Esc/q 恢复原视图、原表单及选中字段，编辑态 `?` 输入普通字符。
真实 PTY 已验证两种入口和两种关闭键；单元测试补充确认中/运行中帮助及事件完成后的焦点。
独立解码器还比对五视图与帮助共 20 次全量/增量渲染，确认输出没有 SGR，且逐列还原的屏幕与来源网格完全相同。

以下按数据完整列出（协议标识、动作值、JSON 字段、路径、确认串语法保留原文）：

### 全局

```text
全局操作
Up/Down 或 j/k：选择菜单或字段；Tab：下一个字段。
Enter：进入视图；字段中开始编辑，再按 Enter 提交草稿。
编辑中 Esc 丢弃草稿；除 Ctrl-C 外的快捷键均被字段消费，? 是普通字符。
F5：概览刷新、监听启动，或审阅当前操作；输入确认串后再按 F5 执行。
Esc：返回菜单；确认时取消；任务运行时请求中止并等待清理。
q：退出；任务运行时请求中止，完成清理后退出。Ctrl-C 也等待清理。
PgUp/PgDn：翻阅日志；空闲或确认时 g 回到末尾并恢复跟随。
? 或 F1：打开帮助；帮助中 Esc 或 q 返回原视图和原焦点。
帮助中 Up/Down 或 j/k 滚动；PgUp/PgDn 翻页；Home/End 到首尾。
```

### Status

```text
状态概览：显示本地配置、接口状态与 OD 闸门；不发帧。
F5 刷新本地状态；不打开 CAN 总线，不发 SDO/NMT。
内核接口名、ERROR-ACTIVE、UP/DOWN 等协议事实保留原文。
```

### Calibrate

```text
标定读取：读取或离线检查 608F/6091 标定与实际位置。
F5 或 F6 审阅读取；输入确认串后按 F5，才执行 SDO 上传。
apply=yes 读取设备；apply=no 使用明确填写的离线标定四项。
标定四项按 608F inc/rev、6091 电机/输出转数顺序填写；不猜分辨率。
读取不写参数、不发 NMT；实时控制器占用时仍需 rt-ack=yes。
```

### Position

```text
位置运动：审阅 PP 绝对目标、脚本行程与电机轴 1度 位移预算。
F6 单独审阅标定和起点读取；执行前须有同一接口、节点的设备快照。
F5 审阅位置操作；确认串包含接口、节点与绝对目标。
修改 node、apply 或 offline-calibration 草稿即废弃旧快照。
apply=no 需填写离线标定、起点和设备限值；这些值不是设备实测值。
motion-log 必须是新 JSONL 路径；单次电机轴位移硬顶为 1度。
OD 闸门、工具侧软行程、速度/加减速度与清理守卫始终有效。
```

### Params

```text
参数维护：备份、插补、传动比、回滚与 EEPROM 保存。
action 可填 backup / interpolation / transmission / rollback / save。
F5 审阅精确对象、值及编码；输入确认串后再按 F5 执行。
backup 是显式 SDO 读取：需新备份路径、apply=no；仍会发上传请求。
其余操作 apply=no 只生成离线计划；apply=yes 写入须完整备份。
transmission 还须独立确认断电后插补参数读回。
save 写 EEPROM，须两段各自输入确认串并按 F5；不会自动保存或重试。
第二段自行构造 SAVE <iface> <node> <十进制序列号>，单空格分隔。
```

### Raw frames

```text
原始帧监听：只接收 CAN 帧；零发送。
F5 启动只接收监听；Esc 请求停止并等待关闭总线。
PgUp/PgDn 翻阅接收日志；不发 NMT/SDO/PDO。
```

### 常驻安全提示

```text
1. F5 才可能发帧；Enter 只选中或编辑。
2. 行程保护仅在工具侧；607Dh 等于没有。
3. 中止时状态字读取失败，电机可能仍使能；用独立急停。
4. save 写 EEPROM 不可逆。
```

## 八、未做的事与最没把握之处

- 没有板端/物理设备验收：任务明确禁止访问板端。本报告的 PTY 是宿主真实 curses，不代表板端实测或电机验收。
- 没有修改 `harness/`、架构文档、协议数值与守卫，没有提交或部署。
- 没有引入 wcwidth/第三方依赖、颜色/SGR 状态。curses 自身初始化/退出可能输出 SGR 重置，网格渲染输出不使用 SGR。
- 支持可打印 W/F 字形，不支持组合字符、ZWJ 字形簇。输入键盘仍沿用 ASCII 字符编辑，现有中文字段值可正确显示和定位；本任务未要求实现中文输入法。
- 最没把握的是不同真实终端的 East Asian Ambiguous 字宽与字体策略；代码固定按一列，宿主 zh_CN UTF-8 PTY 已验收。
  若终端把框线算双宽可用 `--ascii`；这仍需目标终端实际确认，不能用宿主模拟代替。
- 字宽实现按要求统一后，独立缺失 hwtui 工具包时 panel_lines() 不再有自带字宽后备；部署工具包须完整携带共用层。--help 仍按需导入，不因此阻塞。
- 第 3 条 render 契约的 Unicode 限定与 `sanitize()` 显式双宽模式是本次必须披露的两处接口语义；已在正文和 README 说明。
