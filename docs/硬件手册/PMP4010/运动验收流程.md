# PMP4010 单次位置运动验收与标定流程

状态：2026-10-16 **仅工具与本地 mock 验收，未执行真实 CAN、现场运动或抱闸试验**。现场检查、决策、接线和执行由人类负责。厂家的“失电抱紧”是口头声明；下列三项抱闸试验均未验证，不能按勾选项已经存在来认定通过。

依据：[任务 C](给GPT的PDO与验收任务.md#四任务-c运动验收工具建脚本--文档不代替人类执行)、[驱动契约](../../../device/drivers/pmp4010/CONTRACT.md)、[E06](协议/一体化低压伺服电机CANopen通信用户手册-E06.md) §5.1/5.2、§6.1、§6.3.2/6.3.4/6.3.6、表10-7。接口和位速率只由 `device.json` 的逻辑总线映射决定；节点号每次人工指定。

## 一、人类开始前逐项确认

- [ ] 记录日期、操作者、监护人、型号、序列号、固件、配置文件与工具版本/源码 SHA。
- [ ] 确认目标节点身份；总线上仅有一个运动控制主体，原控制任务已按现场规程停止。
- [ ] 负载可靠固定、设独立机械支撑/防坠措施，先在受控小负载环境验收；人员退出危险区。
- [ ] 独立急停、断能和机械防坠措施可用，监护人能立即操作；不能用脚本或通信链路替代。
- [ ] 核实抱闸供电、释放/抱紧逻辑、接线与外部联锁，完成并填写下方三项抱闸试验。
- [ ] 人工确认正负方向、零位、当前位置、机械限位以及两侧行程余量；未经确认不试移动。
- [ ] 确认供电与通信正常，接口为配置位速率、`UP`、`ERROR-ACTIVE`，无待查报警。
- [ ] 确认通信中断后的外部停机保障；已知此前读数 `200Ch:1Bh=0` 仅是历史数据，不代表现在存在通信看门狗。
- [ ] 选择日志存储位置和容量（设备根分区空间有限），每次指定新的 `--motion-log` 文件。
- [ ] 核实尚未 verified 的 OD 条目及后果；若仍需现场旁路，由操作者明确填写 `--od-gaps-bypass '理由'`，旁路不提高可信度。

脚本软行程是轮询保护，存在 SDO 等待和轮询间隔；超调、通信失效和主机故障都可能令保护来不及。只有现场独立急停、防坠及机械限位能提供独立保障。

## 二、抱闸三项试验（未验证，仅人类执行）

以下每次试验均须先放好机械支撑、限制试验位移并安排监护；具体断能/造警方法按现场批准的电气规程执行，本工具不提供这些动作。

- [ ] **断电试验**：按批准规程切断对应电源，实测抱闸是否抱紧、负载是否保持；记录漂移、延迟、测量方法和结果。
- [ ] **失能试验**：按批准规程确认 `Switch on disabled` 后实测抱闸及负载保持；状态字失能本身不证明抱闸已抱紧。
- [ ] **报警试验**：按批准且可恢复的故障试验方案触发报警，确认抱闸和负载保持；不得随意短接、拔线或制造未知故障。
- [ ] 三项全部通过并有人类签字；任一失败或无法安全执行，停止带载运动，登记原因并由人类决定下一步。

## 三、只读标定与单位核对

`--calibrate --apply` 中的 `--apply` **仅授权四项 SDO 上传读取**，该命令零写请求、零 NMT，不使能、不改标定。省略 `--apply` 是离线模式，须给出四个显式模拟值。示例节点仅作占位，现场必须先核实：

```sh
python3 -I device/drivers/pmp4010/tools/pmp4010.py --calibrate --node 1 --apply
```

- [ ] 读取并记录 `608F:01` 编码器增量、`608F:02` 电机转数、`6091:01` 电机轴转数、`6091:02` 输出轴转数；四项均须大于 0。
- [ ] 将四项原始值与设备/上位机显示互核，不采用通用手册的出厂值猜测本机。
- [ ] 计算 `R=608F:01/608F:02`（编码器单位/电机圈），`G=6091:01/6091:02`（电机轴圈/输出轴圈）。
- [ ] 对用户位移 `U=Δ6064`，确认 `Δ6063=U×G`；电机轴角度 `θmotor=U×G/R×360°`，输出轴角度 `θoutput=θmotor/G=U/R×360°`。
- [ ] 换算反向核对：`U=θmotor×R/(360×G)=θoutput×R/360`，确定要限制的是电机轴还是输出轴。
- [ ] 用实际机构量具验证方向、位移和额外机械传动；`6091` 参数换算不替代机构尺寸、零位或机械传动标定。

**非本机示例**：显式模拟 `608F=36000/1、6091=3/1`，`U=10` 得编码器位移 30、电机轴 `0.3°`、输出轴 `0.1°`。不能把输出轴的 `0.1°` 写作电机轴角度。命令可完全离线复算：

```sh
python3 -I device/drivers/pmp4010/tools/pmp4010.py --calibrate --node 1 --dry-run \
  --offline-calibration 36000 1 3 1
```

该位置换算不会开放速度模式。工具仍拒绝模式 2（VM）、3（PV）和 9（CSV）使能；PP 轮廓速度单位是用户单位/s，只用实读标定校验其等效电机 rpm 不超过设备 `6080`，不能据此认定速度模式已验收。

## 四、先离线核对一次小位移

所有值都必须由人类提供。目标为**绝对位置**；软行程为脚本边界，不能以本机接近全域的 `607D` 替代。`--max-displacement` 是人工给定的单次用户位移上限，另外脚本强制其换算后不超过 **1° 电机轴角度**；目标与当前起点必须有非零差。软行程/目标经 `G` 换算也必须在编码器 Int32 范围内。

以下全是模拟值，未读设备，默认和显式 `--dry-run` 都不开真实 CAN：

```sh
python3 -I device/drivers/pmp4010/tools/pmp4010.py --position --node 1 --dry-run \
  --target 10 --velocity 100 --acceleration 100 --deceleration 100 \
  --soft-min -30 --soft-max 30 --max-displacement 30 --move-timeout 10 \
  --start-position 0 --offline-calibration 36000 1 3 1 \
  --offline-limits 1000 100 1000 1000 \
  --motion-log /tmp/pmp-position-offline-001.jsonl \
  --od-gaps-bypass '仅本地模拟帧计划，未授权现场运动'
```

- [ ] 人工逐一替换模拟值；`--offline-limits` 顺序为 `607F` 最大轮廓速度、`6080` 最大电机 rpm、`60C5` 最大加速度、`60C6` 最大减速度。
- [ ] 检查输出的全部“拟发帧”，末行真实发送计数及真实总线打开计数都为 0。示例名义成功路径为 62 请求；真实轮询和清理帧数取决于状态，不能当作现场固定帧数。
- [ ] 检查 JSONL 的 `source=offline_simulation`，确认模拟结果未混入现场实测记录。
- [ ] 确认没有 `1010 save`、NMT、PDO 周期发送或速度模式请求。
- [ ] 给该次现场动作确认目标、速度、加减速度、总体超时、软行程、最大位移和独立急停负责人，填入记录表。

`--dry-run` 与 `--apply` 互斥。日志文件独占创建，已存在就拒绝；重复验收应换新文件名，不覆盖证据。

## 五、人类执行一次 PP 位置验收

**本仓库本轮没有执行本节动作。** 仅在人类已批准现场运动、前面检查全部完成后，使用与本机实读值一致的小位移参数：

- [ ] 从已审核的离线命令中移除 `--dry-run`、`--start-position`、`--offline-calibration`、`--offline-limits`，添加 `--apply`，换用现场日志文件名和现场旁路理由。
- [ ] 若 RT 服务仍活动或状态未知，先解决控制主体冲突；`--i-know-rt-is-running` 仅为显式确认，不能证明已经独占总线。
- [ ] 启动前监护人就位，确认独立急停随时可用。
- [ ] 观察方向、负载和位移；异常立即独立急停，可同时按 Ctrl-C，不能等待脚本确认后再急停。
- [ ] 结束后查看 `before`、`target_reached`、`after_cleanup` 的状态字与实际位置，核对最终 `disabled_confirmed=true` 和 `completed=true`。
- [ ] 人工确认机械已经停止、抱闸抱紧、负载稳定，再撤除试验状态。日志始终写 `mechanical_stop_confirmed=false`，软件状态不冒充机械测量。

执行顺序：运动准备前记录并标记清理责任 → 读实况/四项标定/四项上限 → 校验软行程及单次限幅 → 失能并确认 → 设置 PP、确认模式 → 末速度写 0，速度/加减速度/目标逐项写后读回 → 分步使能确认 → 绝对立即更新 PP 握手 `bit4 0→1→0` 与 `bit12 0→1→0` → 检查目标到达位、实际位置等于目标及模式/状态/实际行程 → 快停、失能确认 → 记录后状态和位置。

PP 完成以**本次新 ACK 握手 + 实际位置到目标**确认，不能拿旧 `target-reached` 当完成。短动作可能在第一次状态采样前完成，因此不强制必须采到 bit10=0。总体超时包含准备、参数和使能；清理使用另外的有界期限，不能因运动期限过了而省掉失能。

## 六、中止与恢复（人类执行）

- [ ] Ctrl-C、总体/状态超时、故障、模式退出、跟随误差、脚本越限或写读不一致时，停止后续运动；检查异常与结果记录。
- [ ] 脚本依次尝试快停、失能并确认 disabled；即使快停失败仍尝试失能。**Quick stop active 不等于失能**，disabled 也不证明机械停止/抱闸状态。
- [ ] 若出现 `失能未确认`、SDO `quarantined`、后状态/位置读不到或日志不完整，按未知状态处理；立即用独立急停/断能和机械支撑处置，监护人员保持隔离。
- [ ] 写 ACK 丢失可能是命令已执行；超时/事务中 Ctrl-C 后保留原 SDO 会话 quarantine。不得用清队列、等一会儿、新建 client、自动重连或重复命令来伪称恢复。
- [ ] 保存日志与接口计数、报警/位置和机械观察记录；没有数据的格子填“未取得”，不要填“停止正常”。
- [ ] 人类独立确认机械安全、通信及设备恢复、旧应答已不可能残留，查明故障/越限原因并重新核对方向、零位、标定与软行程。
- [ ] 由人类决定是否允许重新试验；重启一轮全新记录、小位移检查，不自动回零、不自动报警复位、不自动回滚运动。
