# PMP4010 参数写入工具（任务 B，2026-10-16）

入口为 `device/drivers/pmp4010/tools/pmp4010.py --params`；事务模块为同目录 `pmp4010_params.py`。
**本轮未执行板端参数写入、持久保存或真实 CAN 发帧**，任务书只授权构建工具和离线 mock 验证；现场执行仍由人类另行授权。

`--params interpolation/transmission/rollback/save` 默认全部离线：不打开总线、不读接口、不发 SDO 上传或下载。需要已核对 OD，或者按现有运动工具方式显式给 `--od-gaps-bypass "具体理由"`；理由去掉首尾空白后不得为空，旁路不改变任何 OD 条目的可信状态。`backup` 是显式的只读 SDO 操作，会发上传请求，不能把它说成零帧。真实操作均检查配置、实际接口 UP/ERROR-ACTIVE/bitrate，和实时服务确认。物理接口与速率只来自 `device.json`，节点必须显式给 `--node`。

## 计划与分批

插补时间为 `t × 10^n` 秒，目标配置 `network.sync_period_us=4000` 时：

`4000 µs = 0.004 s = 4 × 10^-3 s`，所以 `60C2:01 = 4`（Uint8，字节 `04`），`60C2:02 = -3`（Int8，小端二补码字节 `FD`）。原实测值为 `20 × 10^-1 = 2 s`，指数原始 `FF` 必须解释为 `-1`。工具用整数分解读取配置周期，不硬编码 4ms，不能精确表示为 Uint8 常数的配置会被拒绝。

**设备是否接受 4ms 仍未证实**。E06 §6.8.4 正文建议 1–20ms，§6.8.5 的示例是 20ms；不能据此宣布此型号 4ms 已验收。应先只写插补两项、独立 save，由人类下一次上电后读回并验明生效，再处理传输类型。传输类型 `--apply` 必须额外给 `--confirm-interpolation-readback`，表示人类已经完成这一步，不是工具自动证明已上电。

| 独立批次 | 对象 | 已有只读实测 | 计划值 |
| --- | --- | --- | --- |
| 插补 | 60C2:01 / :02 | 20 / -1 | 4 / -3（当前4000us配置） |
| 传输类型 | 1400:02–1403:02 | 全部255 | 全部0（同步非循环） |
| 传输类型 | 1800:02–1803:02 | 全部255 | 全部0（同步非循环） |
| 独立保存 | 1010:01 | 状态需备份实读 | 写0x65766173，即小端`73 61 76 65`；随后读回应为1 |

所有对象的宽度、符号和合法范围来自 `od.json` 的 `parameter_objects`，不是从 note 解析。传输类型按 E06 §3.3.3 仅允许0–240、254、255，拒绝保留值241–253。RPDO 宽度采用既有 OD 记录的八对象逐项 `0x4F` 一字节实测证据；表10-5写RPDO Uint32而TPDO Uint8的冲突仍保留在OD note中。若未来固件读回宽度不同，工具拒绝写，不自动猜测宽度。

## 离线用法

以下命令只打印计划；节点号由操作者替换，不提供默认节点。OD尚有缺项时，理由必须结合现场授权填写，示例理由只用于离线审阅。

```sh
python3 device/drivers/pmp4010/tools/pmp4010.py --params interpolation --node "$NODE" --od-gaps-bypass "离线计划审阅"
python3 device/drivers/pmp4010/tools/pmp4010.py --params transmission --node "$NODE" --od-gaps-bypass "离线计划审阅"
python3 device/drivers/pmp4010/tools/pmp4010.py --params rollback --backup /path/to/backup.json --node "$NODE" --od-gaps-bypass "离线计划审阅"
python3 device/drivers/pmp4010/tools/pmp4010.py --params save --backup /path/to/backup.json --node "$NODE" --od-gaps-bypass "离线计划审阅"
```

`--set 60C2:01=4 --set 60C2:02=-3` 可显式指定当前批次值；传输类型采用十六进制地址如 `--set 1400:02=0`。每次仍只能操作一个批次，不能混入1010。整份计划先编码并检查范围，再检查备份，全部完成后才允许开总线。传输类型和插补不得混写于一次普通调用。

## 备份与人工执行顺序

1. 人类确认停机、现场安全、设备身份和独占维护总线。参数工具不发NMT或控制字，不负责停机或失能，不能靠它代替独立安全措施。E06 §9.4「故障检测说明」（提取文本第3931行）将使能时操作保存字指令列为故障，同节还列出电压不足等不能执行命令的情形。
2. 另行授权后，`--params backup --backup /path/to/new.json --node "$NODE" ...` 才会读取实际总线。备份输出路径必须不存在，拒绝覆盖旧备份。任何字段/对象读取失败均不能产生可用备份。
3. 先审阅 `--params interpolation --backup ...` 干跑；经独立现场授权才给同一命令加 `--apply`。apply（包括rollback）及save要求完整备份，先核对接口/速率/节点、再读1018身份四字段与备份完全比较。写入前被动读取一次6041状态字（E06 §10.3 表10-7，Uint16）；bit2置位则提示「电机处于使能状态，请先失能」（逐位定义见E06 §4.1.3 表4-4）。状态读取超时、中止或宽度不符均零写入拒绝。随后先完成整批目标的pre-read，全部成功后才逐项write、readback；异常立即停止后续计划写入，并按下节执行自动恢复，不自动save。
4. 单独运行 `--params save --backup ...` 审阅保存计划。干跑只提示「确认串由备份内容推导，见文档」，不显示确认串。操作者应从备份JSON的 `iface`、`node`、`identity["4"]` 自行构造 `SAVE <iface> <node> <1018:04十进制序列号>`（单空格分隔，序列号为十进制）。实际保存需要独立调用同时给 `--apply --confirm-save "构造的文字"`。不提供交互默许或普通yes。参数保存依据仍为E06 §7.7.1：保存前读回状态必须为1，写magic后读回也必须为1；magic是命令，不能当作保存后的状态值。保存写入一旦尝试，失败也可能已经持久化，工具明确报告结果未知、不可自动撤销，不重试或写回1010状态；须人工独立核验。EEPROM寿命未给出，不要反复save。
5. 由人类在下次上电后独立只读验证插补值和效果。完成后生成新的完整备份，再审阅/授权 `--params transmission --backup ... --apply --confirm-interpolation-readback ...`，然后另一次独立save。一次apply逐项读回不证明下一次上电生效，也不证明同步控制时序达标。

备份版本 `km3.pmp4010.parameters.v1` 包含 UTC 时间、型号、iface、bitrate、node、1018:01/02/03/04四字段，以及12个对象的有符号数值、OD类型、原始小端字节。8项传输类型、60C2两项和1010:01/0B均须存在。1010:00未备份：手册表10-5并未列出该子索引，不按惯例猜读；1010记录级String/ARRAY说明不对应可还原参数。1010:0B备份的只是工厂保存能力/状态，本工具没有写它的入口。JSON篡改、缺项、重复目标、数值与raw不一致、备份与配置目标不匹配在任何发帧前拒绝；设备身份不匹配时只完成身份上传，零下载。

## 回滚

`--params rollback --backup ...` 默认离线，按备份数值展示全部10个可恢复参数。加 `--apply` 后通过身份和状态字检查、整批pre-read，再逐项写回并读回。**始终跳过所有1010命令对象**，绝不能把备份状态1写回当作“还原保存参数”。回滚不会自动持久化，需人类审阅后另行独立save，并在下次上电读回验证。回滚跨两个参数组是明确的恢复操作；应先评估当前故障和备份是否仍适用，不将完整备份误作EEPROM镜像。

参数批次（包括人工rollback）中途失败时采用方案A：按逆序自动恢复本次所有已尝试写入项，并逐项读回确认。恢复目标是本次整批pre-read的现场值，可能不同于备份文件的旧值。失败的当前下载也纳入恢复，因为设备可能已经执行、仅确认或后续读取失败。恢复前再次被动检查6041，仍不发控制字或NMT；某项恢复中止、读回失败或失配，会点名该对象、恢复期望值和读回值（无法读取时标「未知」），尽可能继续恢复先前项，保留原始失败诊断。

超时或事务中断已使SDO会话隔离时，禁止继续发帧，不能靠新建客户端、清队列或NMT擅自解除；恢复中再次超时也立即停止。恢复前状态检查失败同样停止恢复。任何未确认恢复均明确报告「设备处于混合状态或写入结果未知」，列出未恢复项，并给出 `--params rollback --backup <file>` 供人工先离线审阅；完成外部恢复、确认失能和备份仍适用后，才可另行授权加 `--apply`。自动恢复失败不递归重试；自动恢复成功也只证明此次RAM读回，不证明EEPROM或重启生效。整个自动恢复过程绝不自动save，save自身失败也不执行参数自动恢复。
