# PMP4010 速率不匹配根因与后续方案

**日期**：2026-10-15  
**状态**：根因已实测确认，后续方案待用户决策

## 一、根因确认

### 1.1 试验证据

2026-10-15 10:26（Asia/Shanghai），经用户授权，完成如下试验：

- **临时**把板端 `can1` 从 500 kbps 切到 1 Mbps
- 向节点 1 发送**单次** SDO 上传请求：读 `0x1000:00h`（设备类型）
- 节点 1 **正常应答**：`581#4300100092010200`
- 读回值：`0x00020192`（CiA 402 设备类型，profile 0x0192 = 十进制 402）
- 恢复 `can1` 到 500 kbps，ERROR-ACTIVE（但**未**在 500k 下再发请求验证）

完整记录见 [验证记录-2026-10-15.md:160](/home/zakiu/km3/docs/硬件手册/PMP4010/验证记录-2026-10-15.md:160)。

### 1.2 根因

**板端配置 500 kbps，电机出厂默认 1 Mbps，速率不匹配。**

| 来源 | 约定值 |
| --- | --- |
| 项目 `device.json:62` | `"bitrate": 500000` |
| 项目各架构文档 | 500 kbps（设备端程序架构.md:301、实测基线.md:215） |
| E06 表 10-6，`200Ch:03h` 出厂值 | `8`（对应表 3-13 的 1 Mbps） |
| D01 §3.1 通信规格 | CANopen 默认 1 Mbps |

此前观察到的 **ERROR-PASSIVE、零通信、零帧** 的直接原因是速率不匹配导致总线无法解析帧，控制器错误计数递增进入 PASSIVE。

## 二、后续方案（两种，需用户决策）

### 方案 A：板端改为 1 Mbps

**修改板端配置，匹配电机出厂速率。**

| 项 | 操作 |
| --- | --- |
| 配置修改 | `device/config/device.json:62`：`"bitrate": 500000` → `1000000` |
| 持久化 | 同步到板端 `/etc/km3/device.json`，重启 `km3-can.service` 或重启板子 |
| 优点 | 电机无需改动，立即可用；1 Mbps 带宽更高（PMP4010 支持） |
| 缺点 | **与项目架构文档约定不符**（多处文档写明 500k） |
| 文档影响 | 需同步修改：设备端程序架构.md:301、实测基线.md:215、硬件驱动开发路径.md:29，<br>以及 `device.json` 注释（如有）；或在文档中明确「PMP4010 例外为 1M」 |

### 方案 B：电机改为 500 kbps

**用 SDO 写 `200Ch:03h = 6`（500 kbps），电机保存参数并重启。**

| 项 | 操作 |
| --- | --- |
| 准备工作 | 临时把 `can1` 切到 1 Mbps（与当前电机匹配） |
| SDO 写入 | `200Ch:03h` 写为 `0x06`（对应 500 kbps） |
| 保存 | 写 `1010h:01h = 0x65766173`（"save"），持久化到电机 EEPROM |
| 电机重启 | 断电重启，使新速率生效 |
| 板端恢复 | 把 `can1` 恢复 500 kbps |
| 验证 | 在 500k 下读 `200Ch:03h`，确认为 `6` |
| 优点 | **项目文档无需改动**，所有设备统一 500k |
| 缺点 | 需要改电机参数（有风险）；1 次保存约耗 EEPROM 1 次擦写寿命 |

**风险提示（方案 B）**：

- 写 `1010h` 保存参数是**不可逆**操作（除非再写一次恢复）。
- EEPROM 寿命有限（典型 10 万次擦写），但单次保存影响极小。
- 万一写入或保存失败，电机可能需要厂家工具复位。

## 三、两种方案的权衡

| 维度 | 方案 A（板端 → 1M） | 方案 B（电机 → 500k） |
| --- | --- | --- |
| 即时可用性 | ✓ 配置改完立即可通 | ✗ 需改电机参数并断电重启 |
| 文档一致性 | ✗ 需改多处架构文档 | ✓ 无需改文档 |
| 风险 | 低（仅改配置文件） | 中（写 EEPROM，需断电） |
| 带宽 | 1 Mbps（更高） | 500 kbps |
| 未来扩展 | 若后续设备只支持 500k，需再改回 | 所有设备统一 500k |

## 四、我的建议（供参考）

**推荐方案 A（板端改为 1 Mbps）**，理由：

1. **PMP4010 支持 1 Mbps**（E06 §3.6.1 / 表 10-6 出厂值 8），且主板 SIT2515T 最高也支持 1 Mbps（设备端程序架构.md:438）。
2. **项目只有这一种电机**（硬件清单里机身抬降电机 A/B/C/D 都是 PMP4010），无「其它只支持 500k 的设备」需要迁就。
3. **文档改动集中**：只需改 `device.json` 与 3 处架构文档，所有改动在一次提交完成。
4. **风险最低**：不改电机参数，不涉及 EEPROM 写入与断电重启。

**如果选方案 B**：需要一套**安全操作流程**（停机 → 临时 1M → SDO 写 → 保存 → 断电重启 → 恢复 500k → 验证），以及明确的回滚预案（万一失败如何复位）。这套流程我可以写，但需要你明确授权执行。
