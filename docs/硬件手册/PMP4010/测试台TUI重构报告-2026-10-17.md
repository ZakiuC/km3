## 设计判断与实现

1. **相对位置选择方案 A**：使用实时 `6064` 用户单位位置加偏移，冻结为 PP 绝对 `607A` 目标；不使用 IP 的 `60C1`。审阅快照最长 1.5 s，要求速度严格为 0、bit10 为 1；执行前重新读位置、速度、状态与标定，起点有变化即拒绝。共享 PP 路径在设置前、写目标前、触发前再次检查。仍存在最后一次读取到下发之间外部控制器改变位置的时间窗，软件守卫不能锁住外部 RT 控制器，不宣称消除全部竞态。
2. **设零点固定方法 35**：复用现有 `MotionSession.home(35)`；现有 CLI 默认方法 17 保持不变。共享方法按失能→模式 6 并读回→写方法 35 并读回→使能→明确 `6040: 0x0F→0x1F` 边沿→等待本次新 bit10+bit12 完成→恢复 `0x0F` 执行。TUI 额外要求 `6064=0`，清理失能后再次读回；不把 bit15 当通用状态或成功判据。`607C` 非零即拒绝，不写 `607C`，不配置 DI。方法 35 是否需要 DI 配置仍未验证。若旧完成位一直不清除，无法确认新周期，即保守超时，不把旧完成位当作本次成功。归零尝试后清空脚本行程及人工预算，防止沿用旧坐标保护。
3. **后台刷新与隔离**：一个持久总线、一个操作锁串行化 SDO 接收；扫描、刷新、动作各自使用不同 client，不让刷新与动作争抢收包。curses 主线程只读缓存、处理按键和事件，约 50 ms 轮询；空闲时每 0.5 s 安排刷新。动作占锁时刷新让出；SDO 等待在后台线程。成功的整组快照一次性替换，失败保留旧数值并显示失联。任一 client 超时后按接口+节点锁存隔离，显示“已隔离；需外部恢复”，扫描/刷新/动作均不得重建 client 绕过，也没有自动恢复 API。
4. **与 CLI 共用安全逻辑**：CLI `--scan / --motion / --position / --params / --calibrate` 保留。TUI 复用 `refuse_motion`、`position.validate/check_start/check_envelope/check_budget/run`、`MotionSession.home/enable/disable/stop/stop_after_failure`。`check_budget` 从原有 `check_start` 的 1° 预算校验抽取，共享函数可供设零/使能使用；PP 仍走完整 `check_start`。扫描使用与 CLI 相同的 SDO `read_device_type()` 身份读取原语，不依赖心跳，不发 NMT。

界面只保留位置、设零、使能、失能、快停；没有速度模式入口。详情速度先读取 `2006:12` 再标实际单位；`6077` 显示为额定转矩百分比，未凭空换算 N·m。接口由配置读取，节点来自扫描，不硬编码实际总线或设备节点。

## 六项安全要素对照

| 要素 | 保留方式 |
| --- | --- |
| 1° 硬顶 | 共用 `check_budget`，由实读 608F/6091 换算电机轴角度；PP 的 `check_start` 继续调用。人工预算本身大于 1° 即拒绝，不能只靠本次目标较小过闸。 |
| 运行前后包络 | 共用 `check_envelope`；PP 执行前、过程中、后读回均受脚本行程约束。使能后读回/包络失败也走同 client 清理。归零坐标重置成功不套用旧坐标范围，随后强制重填新范围。 |
| 两段确认 | 单项动作输入与实时预览→F5 审阅→手输含动作、接口、节点、目标的精确确认串→F5 执行；错串不执行，审阅后起点/OD/接口变化拒绝。 |
| 中止后失能并确认 | 复用 Quick stop→disable→状态确认；不更换已隔离 client 绕过失败。读取或清理失败如实显示“状态未知”；失能确认不等价于机械停止或抱闸确认。 |
| OD 闸门 | 启动默认只读。首次动作要求输入会话 OD 确认串，随后动作执行仍调用 `refuse_motion`；启动 RT 占用风险另有显式 F5 确认。未降级 FD/DLC 等标准层守卫。 |
| 单次位移上限由人给 | 三个独立数字的安全设置向导输入脚本上下限及预算；预算不内置替用户确认的默认值。每次动作仍用实读标定核验，设零尝试后清空。 |

没有做板端、真实 CAN、真实电机、NMT、部署或提交；这是任务的明确范围。没有开放速度模式，因为速度换算链尚未实现；没有修改架构文档，没有接触禁区。未添加第三方依赖或改写共享渲染/尺寸解析语义。
