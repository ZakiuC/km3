## ⚠ 口径变更：手册「出厂设定」列不作本机比对依据（2026-10-16 厂家答复）

厂家明确：**「厂商资料这块正常是不去做比对的，软件更新后会有变化。出厂值以实际软件读出为准，不要看通讯手册里的值，手册是通用的，对应很多型号。」**

**这条改变的是台账整体的阅读方式**：

- **不可信**：手册的「出厂设定」列 —— 那是**跨型号通用值**，且随固件更新变化。凡涉及「本机该是多少」的判断，一律以**现场读回值**为准。
- **仍然可信**：数据类型、数据宽度、数据范围、访问权限、能否映射、生效方式 —— 这些**不随型号变**，因此已 verified 条目的**结构性字段**不受影响，**不需要重写**。
- **直接后果之一**：`607Dh` 软限位出厂值 ±65535 与本机实测 ±21 亿不符，**本机实测值才是对的**（厂家确认）。详见下方 §A。
- **直接后果之二**：`1018h:01h` 厂商 ID 读 `0x509` 而手册写 `0x2D` —— **很可能不是「手册不配套」，而是同一个「通用手册」的原因**。该疑点从「需厂家澄清的兼容性阻塞」降级为「已知解释」。

## 🔴 垂直轴安全：抱闸（2026-10-16 厂家答复）

**厂家原话：「抱闸不需要你们设置，出厂会配置好，抱闸断电，失能，报警都会抱紧。」**

- **失电抱紧（fail-safe）**：断电、失能、报警三种情况**都抱紧**。垂直轴不会因主站不通信、驱动失能或母线掉电而自由坠落。这是整个垂直轴安全设计的关键一条。
- **抱闸不需要我们配置**，因此 `2002h:04h`（占空比）/ `2002h:0Ah`（延时）/ `200Ah:1Fh`（重力预设）等条目从「待配置」变为**「出厂已配、只需知情」**。
- **⚠ 但「会动作」≠ 「能撑住」**：D01 表 2-1 载 `0HEB`（带制动器款）**制动器保持力矩 ≥ 0.3 N·m**，而 D01 表 3-1 载额定转矩 **0.32 N·m** —— **保持力矩只有额定转矩的 94%**。垂直轴静负载折算到电机轴的力矩 × 安全系数必须 ≤ 0.3 N·m，否则断电时负载会下滑。
- **未做**：未做带载断电试验、失能试验、报警触发试验；未计算本机实际负载折算力矩（依赖机械参数，属人类决策）。**这些应列入现场验收清单。**

## 反馈能力（唯一声明）

**能力分类：`cyclic`，并支持 `readback`。** E06 §3.2 的 SDO 与 §10.3 表10-7 给出状态字、实际位置、实际速度、转矩/电流等可读对象；§3.3 与 §10.1 表10-5 给出 TPDO 通信参数及默认映射（例如状态字/模式回显、位置与速度）。因此有手册依据支持参数回读及 PDO 周期/事件反馈。当前电机的映射、触发方式、节拍与延迟尚未实测，此声明不代表 C++ 周期路径已实现或 1ms 目标已验收。

### B. PDO 映射与同步

E06 §10.1 表10-5 已给出默认 RPDO/TPDO 映射；§3.3.4 明确支持动态修改并给出步骤。**2026-10-16 板端只读探测已实测读回全部映射**（零写请求、69 条读出、两种独立实现互证）：**与手册默认逐条相符，出厂未被改动**——RPDO1 `0x201`←控制字+模式；RPDO2 `0x301`←**目标位置 0x607A + 插补数据 0x60C1:01**（位置运动的通道）；RPDO3 `0x401`←6042h+60FFh；RPDO4 `0x501`←仅目标转矩。TPDO1 `0x181`←状态字+模式回显；TPDO2 `0x281`←实际位置+实际速度；TPDO3 `0x381`←实际速度；TPDO4 `0x481`←实际转矩。

**⚠ 传输类型实测：全部 0xFF（异步），不是同步。** 见 `pdo_transmission_type_measured`。**这直接决定厂家那条要求怎么落地**：「把 PDO 设定为同步模式」是**尚待执行的写操作**（把 1400h:02h 等从 0xFF 改成 0~240），不是既成事实。此前记录里「本机出厂就是同步消费者」的说法**已更正**（`板端只读验收-2026-10-16.md` 留有更正说明）。

SYNC 的存在和消费语义有 §3.3.3、§3.5.1、§6.9~6.11 支撑；`1005h`=0x80 证明设备**可作** SYNC 消费者，但 **`1006h` 中止 `0x06020000`（对象不存在）** → **同步周期无法由从站配置，只能由主站定时器保证**。因此 **SYNC 生产者必须由 km3 设备端自己实现**。手册未记载 SYNC 的 COB-ID/周期/计数器；**未记载不等于证明生产者能力不可能**。需厂家补充同步配置和时序依据，不能据此宣称 8 节点 1 ms 可用。

**断线检测现状（本次实测）**：`200Ch:1Bh` 通信看门狗 = **0（未启用）**、`1017h` 生产者心跳 = **0（未启用）** → **当前没有任何断线检测机制生效**。总线被动监听 2 秒收到 **0 帧**（无 SYNC、无 PDO、无心跳）。

**⚠ `60C2h` 插补时间 = 20 × 10⁻¹ = 2.0 s**（`60C2:01h`=20，`60C2:02h`=0xFF 即指数 −1），手册建议 1–20 ms，**与出厂值差两个数量级**。

**⚠⚠ 更正（2026-10-17）**：此处曾写「CSP 模式下插补时间**必须与 SYNC 周期一致**」，**这句话没有手册依据，是错的**。逐条核对如下：

- `60C2h` 在手册里**只出现在 §6.8 插补模式（IP, mode 7）**（行 2073/2089/2178/2188/2200）与表10-7（行 4689/4690）。**§6.9（CSP）全节一次都没有它**，CSP 的相关对象表（表 6-26）里也没有。
- **两个模式用的是不同的对象**：IP 用 `60C1h:01h`（插补目标位置，§6.8.5「上位机按照**插补周期**写插补位置 60C1h:01h」）；CSP 用 `607Ah`（§6.9.5「上位机按照**同步周期**发送目标位置 607A」）。两者都在 RPDO2 的默认映射里，但是**给不同模式用的**。
- 因此 **CSP 路径的同步周期由 SYNC 帧本身决定，与 `60C2h` 无关**；`60C2h` 只在走 IP 模式时才需要与 SYNC 周期对齐（那时它才叫插补周期）。

**后果**：给 CSP 配套而改 `60C2h` 是**没有依据的动作**。要写它，须先定 CSP 走哪个对象（当前未定，见 `交接-2026-10-16.md` §四）。另 `6065h` 跟随误差阈值=50、`6066h` 跟随误差时间窗=30000（若为 ms 则 30 s）单位仍待核。

## 已登记冲突

- **6073h 最大电流**：E06 §6.11.2 表6-30 写0.01A，§10.3 表10-7 写0.10%。OD只核对字典元数据，`scale/unit` 留空；不得据生成物做已验证的电流上限换算，需厂家澄清。
- 2002h:01h 的宽度/默认值、60C2h 插补默认时间及605Eh权限与正文表述存在差异，详见OD对应note；尚未实机调和。
- §9.2 的32位报警码顺序为 bit31~24反应码、bit23~16自复位、bit15~0故障码；200Eh:01h~11h共17项。默认欠压0x01013220与例中设置0x01003220分别允许/禁止自复位，是策略示例，**不是矛盾**。
- 表4-3 Fault reaction active 的bit1=1，bit4/5不关心；匹配为 `(statusword & 0x004F) == 0x000F`。示例的0x006F不能精确覆盖所有状态。
