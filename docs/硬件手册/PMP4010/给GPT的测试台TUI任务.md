## 一、已核实的事实（**直接采用，不要重新推导**）

### 1.1 可读的实时对象（全部 `verified`）

| 对象 | 索引 | 类型 | 单位/含义 |
| --- | --- | --- | --- |
| `statusword` | `6041h` | uint16 | 见 §1.2 |
| `actual_position` | `6064h` | int32 RO | **用户单位**（`6063h` 才是编码器单位） |
| `actual_velocity` | `606Ch` | int32 RO | **rpm**（但可被 `2006h:12h` 切成用户单位，见下） |
| `modes_of_operation_display` | `6061h` | int8 | 当前模式回显 |
| `error_code_object` | `603Fh` | uint16 | 报警码 |
| `torque_feedback` | `6077h` | int16 | 转矩 |

**⚠ `606C` 的单位可切换**：`2006h:12h = 0` 时是 rpm，`= 1` 时变成用户单位。
**界面显示速度时必须读一次 `2006h:12h` 并标注实际单位**，不能一律写 rpm。

### 1.2 状态字的位

- `bit0` ready to switch on、`bit1` switched on、`bit2` **operation enabled**、`bit3` **fault**
- `bit4` voltage enabled、`bit5` quick stop、`bit6` switch on disabled、`bit7` warning
- `bit9` remote、`bit10` **target reached**、`bit11` internal limit active
- `bit12-13` 模式相关（逐模式不同）
- **`bit15` 不在 4.1.3 的定义里**。手册在 §6.2.2 与 §6.7.2 两处散见地用 `bit15=1` 表示
  「回零完成 / `607Ch` 生效」，但 **4.1.3 本身未定义它** ——
  **不得把 bit15 当成通用状态位到处显示**，只在回零结果里按"手册散见说法"引用。

### 1.3 回零（设零点）的关键事实

`6098h` 回零方式，手册支持 `17~30` 与 `35`。

**`35` 的语义**（E06 第 2007 行）：**「触发原点回零后（控制字 `6040h` 从 `0x0F -> 0x1F`），
以当前位置为机械原点」** —— 不需要限位开关、不需要原点开关。

**这是台架设零点的正确方式。** 但注意：

- **`607Ch`（原点偏移）不是"设零点"**。它是「机械零点偏离电机原点的物理位置」，
  且**只在完成原点回归后生效**（`bit15=1`）。写 `607Ch` 不改变 `6064`。
- **回零前必须配好 DI 功能号**（`2003h` / `2017h`），否则报**参数设置故障**——
  但 `35` 不用开关，是否需要配 DI **手册没说清**。**这一点必须标为未验证**。
- 现有 `--motion home` 默认 `--homing-method 17`（负限位），**不是 35**。

### 1.4 位置控制的既有实现

PP（轮廓位置，模式 `1`，在 `ENABLE_MODES` 里）：
- 目标写 `607Ah`（**绝对**，用户单位）
- 触发是控制字 `0x0F → 0x1F` 的上升沿（`pp_protocol.idle_word` / `trigger_word`）
- 全程有 `position.check_start()` / `check_envelope()` 三重钳制

### 1.5 扫描

`cmd_scan` 用 **SDO 读 `0x1000`** 探节点，**不用心跳**（心跳可能被 `1017h=0` 关掉）。
它**不受 OD 闸门限制**（读身份是规范公共对象，与厂家对象核对状态无关）。
现有实现扫 `1..127`，可传 `--node-range`。

### 1.6 当前现场

只有**节点 1 在线**（`PMPP4010B-CANopen-0HEB-004`，固件 `V3.3`）。
标定 `608F=131072/1`、`6091=1/1` → **1° 电机轴 = 364 用户单位**。
当前位置 `-1464`，状态字 `0x0260`（Switch on disabled）。
`canopen_nodes.json` 里 4 台 PMP4010 的节点号**仍是未分配**。

## 二、界面形态（要做的）

### 2.1 主界面：4 台电机一览

**固定 4 行**（按用户要求），未发现的显示"离线"。

```
┌─ PMP4010 测试台 ─────────────────────────────────────────────────────┐
│ 节点  状态              位置      速度    模式  报警                  │
│>  1   使能              -1464     0       PP    —                    │
│   2   离线              —         —       —     —                    │
│   3   离线              —         —       —     —                    │
│   4   离线              —         —       —     —                    │
├─ 总线 ───────────────────────────────────────────────────────────────┤
│ can1  1 Mbps  ERROR-ACTIVE  错误 0  RT占用 是                        │
├─ 日志 ───────────────────────────────────────────────────────────────┤
│[i] 扫描完成：发现 1 台（节点 1）                                     │
└──────────────────────────────────────────────────────────────────────┘
 S 扫描   Enter 进入   R 刷新   ? 帮助   q 退出
```

**要求**：
- **进入时自动扫描一次**（需要 rt-ack 确认一次，之后记住）
- 之后**周期性刷新在线电机的实时数据**（`6041`/`6064`/`606C` 三个对象，建议 2~5 Hz）
- 扫描或刷新失败**不得清空已显示的数据**，只在状态列标"失联"
- 刷新用**非阻塞**方式：不能让界面卡在 SDO 超时上（`SdoClient` 单次超时后**会隔离节点**，
  见 `canopen.py` 的 `quarantined`）——**隔离后必须显示出来，不能静默重试**

### 2.2 详情 + 控制界面

选中某台后进入：

```
┌─ 节点 1  PMPP4010B-CANopen-0HEB-004  固件 V3.3 ─────────────────────┐
│ 实时（2 Hz 刷新，上次更新 0.3s 前）                                  │
│   状态       使能  (0x026F)                                          │
│   位置       -1464 U  = -4.02° 电机轴                                │
│   速度       0 rpm                                                   │
│   转矩       0.0 N·m                                                 │
│   模式       PP (1)                                                  │
│   报警       无                                                      │
├─ 控制 ───────────────────────────────────────────────────────────────┤
│  [E] 使能    [D] 失能    [X] 快停                                    │
│  [A] 绝对位置 → 目标 (U)                                             │
│  [R] 相对位置 → 偏移 (U, 可负)                                       │
│  [Z] 设零点   (回零方式 35：以当前位置为机械原点)                     │
└──────────────────────────────────────────────────────────────────────┘
 Esc 返回   R 刷新   ? 帮助
```

**操作流程（每个动作都是"输入一个数 → 确认 → 执行"）**：

1. 按 `A` / `R` / `Z` 等动作键
2. 弹出**只含该项**的输入框（例如"绝对位置目标 (U)"，默认值 = 当前位置）
3. **实时预览**（这是关键）：
   ```
   目标 -1414 U = -3.88° 电机轴；相对当前位置 +50 U / +0.137°
   单次位移上限 364 U (1°)；本次 50 U，剩余 314 U
   ```
   超限立即显示"已阻止"及原因
4. 按 `F5` 确认 → **再输一次确认串** → `F5` 执行
5. 执行中显示进度；结束后显示**结果与读回**

### 2.3 必须保留的安全要素（**不得因为"简化"而删掉**）

现有实现里这些是**安全机制**，重构时一个都不能丢：

| 要素 | 为什么不能丢 |
| --- | --- |
| **1° 硬顶**（`check_start` 里 `max_displacement * motor_degrees_per_user_unit > 1`） | `607Dh` = ±21 亿，**电机层面等于没有行程保护**，工具是唯一防线 |
| **运行前后包络检查**（`check_envelope`） | 运动前后的实际位置都必须落在脚本行程内 |
| **两段确认**（审阅 → 确认串 → 执行） | 确认串必须含**接口 + 节点 + 目标**，逼操作者确认"动的是哪台、走到哪" |
| **中止后失能并确认** | 且**如实显示"状态未知"**（清理期读状态字可能失败） |
| **OD 闸门** | 7 项未核对。TUI 里应**默认只读**，运动类操作需显式过闸 |
| **单次位移上限由人给** | 不是"填个默认值就不管了" |

**可以简化掉的**（这些是内部机制，不该暴露给测试人员）：
- `apply=yes/no` 这种原始开关 → 变成明确的动作键
- `离线标定四项` / `离线设备限值四项` / `离线起点` → **从界面移除**。
  实时数据本来就要读设备，没有"离线填四个数"的理由
- `OD 旁路理由` 字段 → 改成**首次运动前的一次性确认对话框**
- `确认实时占用 yes/no` → 改成**启动时的一次性确认**（"RT 控制器正在占用总线，继续？"）

## 三、必须自己判断并说明理由的设计问题

### 3.1 相对位置怎么做

`607Ah` 是**绝对**目标，PP 模式只支持绝对位置指令（E06 §6.9.5 明确「只支持绝对位置指令」）。
**PP 模式没有"相对移动"原语。**

可选做法：
- **A**：先读 `6064` 当前值，`目标 = 当前 + 偏移`，再按绝对位置下发
- **B**：写 `60C1h`（插补目标）—— 但那是**插补模式（IP）**用的，PP 下不适用
- **C**：别的

**要求**：选一条，说明为什么；并说明**方案 A 的竞态**——读 `6064` 到写 `607Ah` 之间
若电机正在动，基准会漂。给出你的处理（例如：仅允许在 `bit10 target reached` 且速度≈0 时相对移动）。

### 3.2 设零点用哪种方式

- **`6098h = 35`**（以当前位置为机械原点）——台架最合适
- 现有 `--motion home` 默认 **17**（负限位），台架上没接限位开关时**会失败或撞**
- 写 `607Ch` **不是**设零点（见 §1.3）

**要求**：用 `35`，并说明：
- 是否需要额外配 DI 功能号（**手册未明说，标为未验证**）
- 触发方式（`6040h 0x0F → 0x1F`）与会话里现有的 `home()` 实现差异
- 完成后**怎么判成功**（`bit15` 是手册散见说法，不是 4.1.3 定义位）

### 3.3 实时刷新的线程与阻塞

`SdoClient` 单次超时后会**隔离该节点**（`quarantined`），后续该 client 永久失败。
所以：
- **刷新不能复用运动用的 client**
- 隔离状态必须**显示给用户**（"节点 1 已隔离：需外部恢复"），不能静默重试
- 刷新节奏要让出按键响应（不能因为 SDO 等待让界面卡住）

**要求**：说明你的线程/轮询设计，以及"界面在 SDO 超时期间仍然响应按键"是怎么保证的。

### 3.4 与 CLI 的关系

**CLI 子命令全部保留**（`--scan` / `--motion` / `--position` / `--params` / `--calibrate`），
TUI **不得复制**其校验逻辑，必须调用同一批函数（`position.validate` / `check_start` /
`check_envelope` / `refuse_motion` 等）。
