# PMP4010 抱闸手动听声测试（2026-10-19）

本入口让现场人员一次一次请求松闸/抱闸并听声。它复用现有驱动自动抱闸相关的使能/失能路径；不直接驱动抱闸输出、不改DO或抱闸参数。是否听到开合声、机构是否真正松闸/抱闸，需要现场确认。它不能确定此前几乎不动的根因，也不构成维修或实机验收结论。

## 操作

使用配套 `run-brake.sh`，或在完整工具目录内运行：

```sh
python3 pmp4010_brake.py --node 1 --motion-log /可写目录/本次新建-brake.jsonl
```

日志必须使用新路径；已有日志不会覆盖。总线仍从原配置的逻辑 `can-2` 解析，入口不提供物理接口/位速率覆盖。`--help`、导入模块、无交互终端路径均不打开CAN。

1. 启动后按 `Enter` 确认总线占用与现场连接；这一步只读取，不使能。
2. 核对屏幕列出的OD未核对项，按 `Enter` 仅授权本次人工听声。OD可信度不变。
3. 按 `1` 或 `e`，核对本次保持目标，再按 `Enter` 请求松闸。**使能会产生保持力矩**，需先确认机构与负载安全。程序保持Halt，不执行位置运动。
4. 听一次声音；按 `2` 或 `d` 立即失能，请求抱闸。**这一步立即撤销保持力矩**，不再弹出确认。然后再听一次声音。再次松闸必须重新 `1/e → Enter`。
5. `Space/x` 随时请求软件快停；`q` 安全退出。软件控制不能代替独立急停。

没有自动计时、开合循环、点动、相对/绝对位移、零点、速度、步长或测程编辑器。重复按松闸键时，已有保持目标/使能状态会明确提示先失能，不会暗中失能再使能。启动、取消和失能都不会隐含使能。

`t → Enter` 仅沿用现有Warning 2312手动复位：不自动使能、不重放目标。其他保护锁定与真实通信隔离不允许这样恢复。

## 实际发送与界面语义

松闸请求沿用 `SimpleController` 的保持动作：冻结本次采样的6064为607A，读回并核对提交ACK，控制字为 `0106 → 0107 → 0127 → 0137 → 0127 → 012F`。最终保持Halt，没有 `002F → 003F → 002F` 的Go序列。保留OD确认、607Ch非零拒绝、607Dh限位、故障/跟随误差、参数与标定保护、同客户端通信隔离、JSONL日志和原有锁/刷新机制。

听声保持沿用授权时冻结原点的 **±1°电机轴会话保护**，与驱动限位取交集；不会在后续开合时重新冻结会话原点。这是保持听声入口，不是测程入口；现有守卫没有减弱。

`2/d` 复用安全失能 `6040h=0000`，已连接但未授权松闸时同样可用；未连接时不打开总线。`q` 保留原有退出契约：对本会话接管过的节点发 `6040h=0006` Shutdown，读取6041h确认operation enabled bit2清零，然后关闭总线。退出不是新的使能动作。已隔离的客户端禁止重试，状态未知须现场独立处理。

主界面显示CW、SW、603F报警，以及“松闸请求：已使能保持”或“抱闸请求：已失能”。这些是电气请求/状态。界面始终显示“机械抱闸状态：未知，需听声确认”。不把通用DO位当作内置抱闸机械反馈。

故障/通信丢失后，界面将当前实读状态标为未知，优先显示首次失败诊断中的603F十六进制及中文含义、6041、CW和CW来源；旧完整快照明确标为历史。若本轮在SW故障处中止、尚未读取603F，诊断603F显示未知，不用历史零值补齐。停止确认只表示电气失能，机械停止/抱闸仍未知；这些显示不会新增SDO请求。

**操作请求确认 ≠ 机械开合确认。**
