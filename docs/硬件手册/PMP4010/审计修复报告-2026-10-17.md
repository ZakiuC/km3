## 二、修复4：语义与理由

保留 `max_late_us` 为 Tick 入口相对原定 next_us_ 的最大唤醒迟到，跳槽前采样；它和发送 deadline 是两个不同量，原审计“基准不一致、Skip低报”不能直接当成减法缺陷。新增 `min_send_margin_us` 为自成功 Start 后最小的 `(next_us_ + period_us_) - observed`。BeforeSync 失败/预发超期时在该处采样，Send/SendConfirmed 则在返回后采样，每个有可表达 deadline 的尝试一次。

正数表示余量，零表示恰在 deadline，负数表示超期；周期预发检查仍拒绝等于 deadline。INT64_MAX 专用无样本哨兵、展示为 n/a，样本饱和至 INT64_MIN..INT64_MAX-1，不可表达 deadline 不采样，成功 Start 清零统计并重置哨兵。新增 int64 原子 lock-free 静态断言，运行路径保持无分配纪律。

定点测试实际覆盖 period=4000µs、唤醒仅迟到1µs、Send 推进4500µs：max_late_us=1 而 min_send_margin_us=-501。普通 Send 观察的是入队返回，Confirmed 观察的是确认调用返回；两者均为软件时钟观测，不能冒充物理 CAN TX 时间或 CSP 时序验收。main 仅增加统计展示，没有建立 PdoSession 或生产运动入口。

## 三、修复2：选择方案A

选择自动回滚，避免可恢复的参数批次失败留下混合 RAM 参数。先对整批取本次 live pre-read，逐项写入前登记 attempted，失败项可能已生效但丢 ACK，因此恢复包含失败尝试项并逆序逐项读回确认；恢复目标是本次 pre-read，不能拿历史备份覆盖本次原值。恢复前再次被动检查失能。

保留同一 SDO client 与 quarantine；会话已隔离、状态读取失败或恢复中断时不擅自恢复通信、不重试，明确报告混合/未知状态与人工 rollback 备份路径。原始失败对象、期望值、实际/未知值与异常均保留。保存命令失败可能已持久化，不可自动撤销；不重试、不自动 rollback/save。任何恢复都不自动写1010持久保存。

apply/save 以及显式 rollback 执行前均被动读取 OD 已核对 Uint16 状态字，bit2置位拒绝，超时/中止/宽度错误也拒绝。没有控制字或 NMT 操作。小项同时拒绝 strip 后为空的旁路理由，save 干跑只提示从备份推导、见文档，不泄露 token。

## 四、修复3：变异证据

新增手写线缆向量覆盖8张映射共36个有效字节，并分别检查 Encode 和 Decode；RPDO2 的 `0x607A0020` 对应 `20 00 7A 60`。变异只交换每个4字节字段相对偏移2/3，保持0/1；对称变异证明旧往返断言盲点，单侧变异证明新断言独立覆盖两侧。
