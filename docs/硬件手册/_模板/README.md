> **CAN 端口命名**（用户明确纠正过，勿再漂移）：
> 清单里的 `CAN-x` 指**主板 CAN 的第 x 个口**，所以 `CAN-1` = 内核 `can0` = 逻辑名 `can-1`，
> `CAN-2` = 内核 `can1` = 逻辑名 `can-2`。
> 陷阱：内核里的 `can2` 是 **USB 转 CAN 模块**，**不是** CAN-2。下标差一位，驱动就会对错总线。

## 反馈能力

声明该硬件**有没有回读**，这决定工具与界面能不能显示「当前状态」：

| 值 | 含义 |
| --- | --- |
| `none` | 无反馈（如继电器）。**不得**维护「当前状态」的权威副本，界面须显式标注无反馈 |
| `readback` | 可按需读取状态。驱动须提供读取路径 |
| `cyclic` | 周期上报（如 CANopen TPDO / 心跳） |
