# 架构设计摘要

km3 是一套墙面/绳索作业机器人系统，三端协同：设备端 TL3588（C++17）、
上位机 云卓 G30（Android/Kotlin）、服务器端 阿里云 VPS（C++17）。
目标：高效、解耦、易于长期开发、方便 agent 与人类协同。

## 二、核心决策

| 决策 | 结论 |
| --- | --- |
| 语言 | C++17（设备端 + 服务器端），Kotlin（前端，不用 JNI） |
| 部署 | 原生：设备端 systemd，服务器端 systemd + nginx。**不用 Docker** |
| 数据库 | PostgreSQL 单库（关系 + 时序分区表 + 会话）。**不用 Redis/InfluxDB/RabbitMQ** |
| 实时架构 | RT 线程 → 预分配无锁环形缓冲 → 边界线程 → 网络 |
| CPU 绑定 | 实时 CPU4–7（A76），非实时 CPU0–3（A55） |
| 设备认证 | Ed25519 挑战应答（不用 mTLS/CA/CRL） |
| 用户认证 | 服务端会话票据（不用 JWT），可即时吊销 |
| 命令签名 | 用户侧 Ed25519 私钥签名，**设备端验签**（服务器非唯一验签点） |
| 固件签名 | 离线签名，服务器不持私钥 |
| 设备进程数 | 3 个（rt-controller / core / video），不是 7 个 |
| 存储 | 程序 `/opt/km3`，配置 `/etc/km3`，数据 `/data`（UUID 挂载）。根分区仅 4.2GiB |

## 三、四条网络路径

| 路径 | 链路 | 状态 |
| --- | --- | --- |
| A | 上位机 ↔ 设备（直连，Protobuf） | 主 |
| B | 上位机 ↔ 服务器 ↔ 设备（JSON） | A 失败时降级 |
| C | 设备 ↔ 服务器（JSON） | 主 |
| D | 设备 ↔ G30 ↔ 服务器（隧道） | C 中断时降级 |

规则：任一时刻只有一条命令通道生效；切换必须对用户可见，在途命令标记为
「结果未知」；看门狗阈值随通道调整并在切换时重置。详见 `通信协议规范.md` §一、§五、§八。

## 四、必须实机验证的事项（不得当作已有能力）

| 项 | 现状 |
| --- | --- |
| 千兆链路 | eth0 实测 100Mb/s；eth1 DOWN |
| 6 路摄像头 | **未接入**；分辨率/帧率/格式未定 |
| CAN FD | **主板不支持**，CANfd 设备须走 USB 转 CAN |
| A/B 双系统 | **不具备**，现为普通分区布局 |
| 自动回滚 | **不具备**，需看门狗 + 启动标记配合 |
| 看门狗 J3 | 跳线状态与超时范围待确认 |
| CPU 隔离 | `isolcpus` **未配置** |
| 1ms 周期唤醒抖动 | **已实测 1 µs**（空循环体；端到端响应仍未实测） |
| 实时性端到端 | 需在真实负载下测最坏响应 |

## 六、实施计划

排期原则：**先打通端到端可验证闭环，再扩展**。以功能 ID 标注交付物。

### 阶段 0：环境与骨架（第 1 周）

- 交叉编译工具链、依赖安装（`tools/install-deps.sh`）
- 设备端 / 服务器端 CMake 骨架，proto 定义
- 输出：本仓库结构可构建

### 阶段 1：设备端最小闭环（第 2–4 周）

- 实时边界（环形缓冲 + 边界线程）、HAL 骨架、模拟设备
- 单条总线打通（先 RS485，再 CAN）
- **交付：F02 的雏形**（一条命令从本地注入到执行并回 result）

### 阶段 2：直连通道（第 5–6 周）

- 路径 A（TCP + Protobuf 帧）实现与联调
- **交付：F01 F02 F03 的最小可用版本**

### 阶段 3：服务器端接入（第 7–10 周）

- 服务器骨架（Asio + Beast）、数据模型、迁移
- **交付：B02 B04 B05**（授权、设备管理、命令排队与 ACK 全链路）
- 关键：ACK 链路必须三端闭合，前端不得出现硬编码成功

### 阶段 4：认证与数据（第 11–13 周）

- 挑战应答、命令签名与验签、防重放
- **交付：B09 B08**

### 阶段 5：前端完整化（第 14–17 周）

- 登录、设备选择、配置面板（动态 schema）、视频、告警
- **交付：F05 F06 F04 F08**

### 阶段 6：OTA（第 18–20 周）

- 增量热更新（版本目录 + 符号链接）、整包停机、签名校验
- **交付：F07 B07 B11**

### 阶段 7：管理与上线（第 21–24 周）

- 日志中心、工时统计（待口径）、跨环境
- **交付：管-F01 至 管-F06 B10 B11**

**人力现实**：单人 + agent 协作，上述为估算区间，非承诺。
真正的成败杠杆是砍掉不必要的中间件与进程，不在语言选择。

## 七、风险与决策点

| 风险 | 缓解 |
| --- | --- |
| C++ 迭代速度慢于 Go | 先固定头文件与协议，agent 只填实现；CI 跑 sanitizer |
| Asio 回调生命周期与并发 | `shared_from_this` + strand 保护；**必跑 TSan** |
| 实时指标仅测了时基 | 唤醒抖动已测（1 µs，空循环）；**执行时间与端到端响应仍缺**，需在真实负载下补测 |
| A/B 与自动回滚不具备 | 显式列为后续改造，文档不承诺未验证能力 |
| 管理端 Web 技术栈已定（Vue 3 + TS） | 见 `管理端Web程序架构.md`；B10/B11 口径仍待定 |
| 工时/跨环境口径未定 | 需用户先定口径再实现 |

**决策点**：若服务器端进度落后设备端超过 4 周，可在评审时改为 Go 单二进制。
此决策由用户拍板，文档如实记录而非含糊处理。
