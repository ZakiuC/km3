# OTA 升级方案

覆盖清单 F07（控制台固件与组件升级）、F06（后台 OTA 下发页）、B07（固件文件与跨环境 OTA）。
三件事：**整包停机更新**、**增量热更新**、**回滚**。

## 一、能力边界（先读这一节）

| 能力 | 现状 | 第一版做法 |
| --- | --- | --- |
| 整包停机更新 | 可做 | 停机 + 单分区替换 + 失败手工恢复 |
| 增量热更新 | 可做 | 版本目录 + 符号链接原子切换 + 服务重启 |
| 自动回滚 | **当前不具备** | 内核级重试 + 看门狗兜底 + 启动成功标记，逐步演进 |
| A/B 双系统 | **当前不具备** | 列为后续改造任务，见 §五 |

**A/B 为什么现在不具备**（必须如实记录，不能当作已有能力）：

- 实物为**普通分区布局**：`mmcblk0p1`(uboot 4MiB) / `p2`(misc) / `p3`(boot 64MiB) /
  `p4`(recovery 128MiB) / `p5`(backup 32MiB) / `p6`(rootfs 14GiB) / `p7`(oem 128MiB) /
  `p8`(userdata 43.9GiB)。
- A/B 需专用镜像与分区布局，且**只支持 eMMC 启动**。
- **文件系统引导失败时可能不会自动重启**，重试计数无法耗尽——即「自动回滚」不成立。
- 改造代价：重新分区 + 重刷专用镜像 + 丢失当前 rootfs（含已验证的 RT WiFi 驱动修复）。

## 二、更新对象分类

关键前提：**不是所有东西都能热更新**。

| 对象 | 更新方式 | 理由 |
| --- | --- | --- |
| `km3-core`（网络/配置/日志/OTA/采集） | 增量：版本目录 + 符号链接切换 + 重启 | 非实时，重启窗口可接受 |
| `km3-video` | 增量：同上 | 同上 |
| 辅助能力（视频参数、上报策略、日志过滤） | 可选 `dlopen` 插件 | 不含实时路径；带 `ABI_VERSION`，不匹配即拒绝加载 |
| `km3-rt-controller` | **整包停机** | 实时进程内不能做热替换 |
| 内核 / 设备树 / 驱动模块 | **整包停机** | 模块 vermagic 与内核绑定 |
| 前端 App | Android 常规升级 | 独立于本方案 |

**为什么不用「进程内热加载」**：RT 进程里有已注册回调、已分配缓冲、持锁状态，
`dlopen` 替换要考虑对象生命周期、ABI 匹配、卸载时的实时语义，收益远低于成本。

## 三、增量热更新（主路径）

### 3.1 目录布局

```
/opt/km3/
├── releases/
│   ├── 1.2.0/km3-core
│   ├── 1.2.1/km3-core
│   └── 1.3.0/km3-core
└── current -> releases/1.2.1      # 符号链接，原子切换
```

systemd 单元的 `ExecStart` 指向 `/opt/km3/current/km3-core`。

### 3.2 切换流程

```
1. 停止目标服务
2. 下载新版本到 releases/<new>/
3. 校验 SHA256 与签名
4. 原子切换：ln -sfn releases/<new> current.tmp && mv -T current.tmp current
5. 启动服务，探测健康（进程存活 + 端口就绪 + 关键功能自检）
6. 失败则切回 releases/<old>/ 并重启
```

关键点：符号链接切换用 `mv -T` 保证原子性；**不删除旧版本目录**，
回滚只需切回链接。

### 3.3 与配置、数据的兼容

- 配置：新版本必须能读旧配置；新增键有默认值。
- 本地数据：`sensor_data` 每条带 `schema_version`。
  **新固件必须能读旧 schema；回滚后的旧固件遇到未来 schema 必须跳过而非崩溃。**
  Protobuf 的 unknown field 机制天然支持，但要求**不得复用已废弃的 field number**。

## 四、整包停机更新

### 4.1 流程

```
1. 下发 ota_offer {kind: "full", version, url, size, hash, signature}
2. 设备下载到数据盘 /data/ota/，校验 SHA256 + 签名
3. 写启动成功标记前先清空 /data/ota/boot_ok
4. 停机，写入新镜像到目标分区
5. 重启
6. 应用启动后自检通过，写 /data/ota/boot_ok
7. 上报 ota_report {status: "ok"} 或 {status: "failed", error_code}
```

### 4.2 失败恢复（三段式）

自动回滚当前不具备，用三段式尽力恢复：

| 阶段 | 机制 | 覆盖场景 |
| --- | --- | --- |
| 1 | 内核级重试计数 | 内核引导失败 |
| 2 | **外部看门狗 MAX6369** | 系统整体卡死（含内核挂起、文件系统引导卡住） |
| 3 | 应用层启动成功标记 | 应用启动失败 / 自检不通过 |

**看门狗兜底是必须的**——文件系统引导失败时不触发自动重启，只能靠硬件看门狗复位。
喂狗条件：运动控制循环按周期推进、安全线程存活、关键传感器在线、无未处理安全故障。

**当前 J3 跳线状态与超时可配置范围待确认**，需实机验证。

### 4.3 回滚规则

**「版本单调递增」与「回滚」不是互斥规则**，拆成两条独立规则：

1. **签名校验**：任何版本都必须签名有效，降级也不例外。
2. **降级保护**：默认拒绝降级；管理员可携带**显式授权标志 + 审计记录**执行降级。

回滚目标为 `ota_deployments.prev_version`——**来自设备侧记录的上一版本**，
不是服务端在部署时用「设备当前版本」推导（那会在回滚后覆盖自身，形成不可逆状态）。

## 五、A/B 双系统（后续改造任务）

若将来要做，前置条件与代价：

| 项 | 内容 |
| --- | --- |
| 分区 | 需专用 A/B 镜像布局（boot_a/boot_b、system_a/system_b） |
| 启动介质 | 仅支持 eMMC 启动 |
| 代价 | 重新分区 + 重刷镜像 + **丢失当前 rootfs（含 RT WiFi 驱动修复）** |
| 配合 | 需专用 updateEngine + 启动重试 + 成功标记 + 看门狗 |
| 限制 | 根文件系统引导失败可能不自动重启，重试计数无法耗尽 |

未完成验证前，**文档不得承诺「更新失败自动回滚」**。

## 六、固件签名与分发

### 6.1 离线签名流程

```
# 开发机（持 Ed25519 私钥，不进生产路径）
tools/sign-firmware.py --key ~/.km3/fw_signing.key \
    --in  build/km3-firmware-1.3.0.tar.zst \
    --out dist/
# 产出：firmware.bin + firmware.sig + manifest.json
```

`manifest.json`：

```json
{ "version": "1.3.0", "model": "wcr", "size": 52428800,
  "sha256": "...", "min_version": "1.0.0", "kind": "full" }
```

**服务器不持私钥**——被入侵不等于能签发任意固件。轮换 = 一次 OTA 更新设备内公钥表。

### 6.2 分发

经 nginx 分发（`sendfile` + HTTP Range 支持断点续传）。
设备下载到 `/data/ota/`（数据盘，非根分区）。

## 七、跨环境

`firmware.env_id` 与 `devices.env_id` 必须匹配。禁止把生产固件推到演示机，
或把演示固件推到生产机。**部署前强制校验**，不匹配返回 `EINCOMPATIBLE_VERSION`。

支持灰度：先发演示环境验证，再发生产；生产可指定设备子集。

## 八、验收清单

| 项 | 要求 |
| --- | --- |
| 增量更新 | 切换 + 重启 + 失败回滚，全程不中断实时控制 |
| 整包更新 | 停机窗口内完成，重启后自检通过 |
| 签名 | 篡改固件被拒绝，缺失签名被拒绝 |
| 掉电 | 更新过程中断电，重启后能恢复（或明确失败） |
| 数据兼容 | 新旧固件互相读写本地缓存不崩溃 |
| 跨环境 | 环境不匹配被拒绝 |
| 看门狗 | 模拟卡死后硬件复位并恢复 |

**掉电注入与根文件系统损坏两项必须实测**，当前资料记为未完成测试。
