#### 2.1.1 MotionControl - 运动控制模块

**职责**:
- 爬绳器伺服控制 (雷赛 L7P, RS485-1 / ttyS3)
- 吊点位置电机控制 (IM42ET-P, RS485-1 / ttyS3)
- 推进风扇电调控制 (ESC, CAN-1, CAN 2.0B)
- 机身抬降电机 A (PMP4010, CAN-2, CANopen)
- 毛刷抬降电机 (YZ-AIM-CanOpen, CAN-2, CANopen)
- 刮条抬降电机 (YZ-AIM-CanOpen, CAN-2, CANopen)
- 机身抬降电机 B (P65MAX-S, USB转CAN模块-1, CANfd)
- 毛刷旋转电机 (直流有刷, 经继电器模块通断, 无调速与反馈)
- 运动轨迹规划和插补

**实时性指标（设计目标，尚未实测）**:

下列数值是**设计目标，不是实测结果**。厂家 cyclictest 数据（1ms 间隔、12 小时、内存锁定、
SCHED_FIFO）给出的是**线程唤醒延迟**：CPU4–7（A76）满载最坏 10/15/12/10 µs，
CPU0–3（A55）满载最坏 80/23/38/66 µs。**唤醒延迟不等于端到端控制响应**——
后者还包含 RS485/CAN 帧时间、驱动器解析时间和机械动作时间。

| 指标 | 目标值 | 实测状态 |
| --- | --- | --- |
| 周期唤醒抖动 | 温和 | **已实测 1 µs**（1 kHz × 10000 周期，0 overrun） |
| 控制回路执行时间 | ≤ 1ms | **未实测**（循环体当前为空） |
| 端到端控制响应 | ≤ 5ms | 未实测 |
| 紧急停止链路 | 目标 < 1ms | **无依据，未实测** |

首个实测点的条件与**它不证明什么**，见 `实测基线.md §七`。
一句话：1 µs 是"时基与调度可用"，不是"控制回路够快"。

**当前实测范围**（`实测基线.md §七`）：1 kHz 下 10000 周期、最大迟到 1 µs、0 overrun，
条件为 `SCHED_FIFO` 90 + CPU7 + 内存锁定 + 未隔离 CPU；**循环体为空**。

**验收前必须实测**：在接入视频、USB 外设、WiFi 与 SSD 写入的真实负载下，测量每条控制回路的
**最坏**响应时间，并测出控制回路的**执行时间上界**（当前完全没有数据）。各驱动器的实际控制周期与反馈延迟尚未确认——RS485 半双工在 115200bps 下
单个 Modbus 事务约需 800–1000 µs，**本身就接近 1ms 周期**，需实测确认能否满足。

**线程模型**:
```cpp
void MotionControlThread() {
    SetThreadPriority(SCHED_FIFO, 95);
    SetCPUAffinity({0, 1, 2, 3});
    LockMemory();
    
    const auto period = std::chrono::microseconds(1000); // 1ms
    auto next_wakeup = Clock::now() + period;
    
    while (running_) {
        // 1. 读取传感器反馈
        ReadFeedback();
        
        // 2. 执行控制算法
        UpdateControl();
        
        // 3. 输出控制指令
        SendCommands();
        
        // 4. 更新状态到消息总线 (异步)
        // 4'. 仅把定长状态记录写入预分配环形缓冲（无锁、无分配、无系统调用）。
        //     序列化与消息总线转发由 km3-rt-controller 的 BoundaryThread 完成。
        //     禁止在 RT 线程内直接调用消息总线：ZMQ 的 send/serialize 会 malloc 并可能阻塞。
        state_ring_.Push(current_state_);
        
        // 5. 等待下一周期
        Clock::sleep_until(next_wakeup);
        next_wakeup += period;
    }
}
```

#### 2.1.3 CANBusCtrl - CAN总线控制模块

**职责**:
- CAN-1 (主板 can0, CAN 2.0B): 推进风扇电调 ESC (2台)
- CAN-2 (主板 can1, CAN 2.0B): 机身抬降电机 A (PMP4010, 4台, CANopen)、
  毛刷抬降电机 (YZ-AIM-CanOpen, 2台)、刮条抬降电机 (YZ-AIM-CanOpen, 2台)
- USB转CAN模块-1 (CANfd): 机身抬降电机 B (P65MAX-S, 4台)

**逻辑名与端口的映射（唯一权威，其他文档与代码一律以此为准）**:

`CAN-x` 是**主板 CAN 的第 x 个口**（定义出自 `硬件设备清单.xlsx`），
因此它的数字与内核接口名**差一位**，这是最容易写错的地方:

| 逻辑名（配置里用） | 内核接口 | 硬件含义 | 挂载设备 |
| --- | --- | --- | --- |
| `can-1` | `can0` | 主板 CAN 第 1 口，CAN 2.0B | 推进风扇电调 ESC ×2 |
| `can-2` | `can1` | 主板 CAN 第 2 口，CAN 2.0B | 抬降电机 A（PMP4010 ×4）、毛刷、刮条 |
| `usb-can-1` | `can2` | **USB 转 CAN 模块**，CANfd | 抬降电机 B（P65MAX-S ×4） |

> **陷阱**：USB 转 CAN 模块的接口名恰好是 `can2`，而它**不是**主板的 `CAN-2`。
> 主板 `CAN-2` 是 `can1`。把二者当同一个会让驱动对错总线，
> 而现场表现只是"电机不动"或"动错台"，极难反查。
> 因此代码与配置里**一律用逻辑名**（`can-1`/`can-2`/`usb-can-1`），
> 内核接口名只在 `device/config/device.json` 出现一次。

> **写法约定**：协议名写 `CAN 2.0B`——`CAN` 与版本号之间用**空格，不加连字符**。
> 加了连字符后，它形如"CAN 加数字"，会被读成主板端口号。
> 本仓库禁止该写法，由 `tools/check-docs.sh` 的第 4 项检查强制
> （该检查自身用转义写法匹配，因此本段不会触发它）。

**能力边界（实测依据）**:

主板两路 CAN 由 SPI0 外挂 SIT2515T-I/SO + NSI1050 实现，仅 **CAN 2.0B，最高 1Mbps，
本板不支持 CAN FD**。因此：

- 标称 CANopen 的设备走主板 CAN-1 / CAN-2。
- 标称 **CANfd** 的设备（P65MAX-S）**必须走 USB 转 CAN 模块**，不能接到主板 CAN 上。
- 本模块需同时维护两套协议栈：主板侧的 **CANopen**（SDO/PDO/NMT）与
  USB-CAN 侧的 **CANfd 原生帧**。两者在配置里按总线声明，代码不得混用。
- **继电器模块不在 CAN 上**，它挂在 USB-RS485 模块上（见 2.1.4）。ZMQ 之前的版本文档把它
  写在 CAN-2 下，是错的。

**SocketCAN 使用**:
```cpp
// 初始化
int InitCAN(const std::string& interface) {
    int sock = socket(PF_CAN, SOCK_RAW, CAN_RAW);
    
    struct ifreq ifr;
    strcpy(ifr.ifr_name, interface.c_str());
    ioctl(sock, SIOCGIFINDEX, &ifr);
    
    struct sockaddr_can addr;
    addr.can_family = AF_CAN;
    addr.can_ifindex = ifr.ifr_ifindex;
    bind(sock, (struct sockaddr*)&addr, sizeof(addr));
    
    // 设置过滤器
    struct can_filter filters[N];
    setsockopt(sock, SOL_CAN_RAW, CAN_RAW_FILTER, 
               &filters, sizeof(filters));
    
    return sock;
}

// 发送
void SendCANFrame(int sock, uint32_t can_id, const uint8_t* data, uint8_t len) {
    struct can_frame frame;
    frame.can_id = can_id;
    frame.can_dlc = len;
    memcpy(frame.data, data, len);
    write(sock, &frame, sizeof(frame));
}

// 接收 (RT线程中)
void ReceiveLoop(int sock) {
    struct can_frame frame;
    while (running_) {
        ssize_t nbytes = read(sock, &frame, sizeof(frame));
        if (nbytes == sizeof(frame)) {
            DispatchCANFrame(frame);
        }
    }
}
```

#### 2.1.4 RS485BusCtrl - RS485总线控制模块

**职责**:
- RS485-1 (主板 ttyS3): 爬绳器伺服驱动器 (雷赛 L7P) + 吊点位置电机 (IM42ET-P)
- RS485-2 (主板 ttyS5): 吸盘鼓风机 (3台) + 风刀鼓风机 (2台)
- USB-RS485 模块-1: 机身超声波测距 (KS114-V100, 2台) + 姿态传感器 IMU (SINDT-485)
  + 液压/水压变送器
- USB-RS485 模块-2: 温湿度传感器 (SHT30) + 24V 电源 + 48V 电源 (NVVV-RS485)
- USB-RS485 模块-3: 吸盘气压传感器 (JC-102-RS485, 3台)
- USB-RS485 模块-4: **继电器模块 (ZS-DI0-R-10A-10-R-485, 1个, 10入10出)**

**开关量约束**: 继电器模块是纯开关量输出，**没有位置或速度反馈**。由它驱动的
**毛刷旋转电机**（直流有刷, 1台）只能开/关，不能调速；安全策略与状态显示不得依赖其状态回读。

**接口**:

```cpp
int ConfigureSerial(const std::string& device, const RS485Config& cfg) {
    int fd = open(device.c_str(), O_RDWR | O_NOCTTY);
    
    struct termios tty;
    tcgetattr(fd, &tty);
    
    cfsetispeed(&tty, BaudrateToSpeed(cfg.baudrate));
    cfsetospeed(&tty, BaudrateToSpeed(cfg.baudrate));
    
    tty.c_cflag &= ~CSIZE;
    tty.c_cflag |= CS8;        // 8 data bits
    tty.c_cflag &= ~PARENB;    // No parity
    tty.c_cflag &= ~CSTOPB;    // 1 stop bit
    tty.c_cflag |= CREAD | CLOCAL;
    
    tty.c_lflag &= ~(ICANON | ECHO | ECHOE | ISIG);
    tty.c_iflag &= ~(IXON | IXOFF | IXANY);
    tty.c_oflag &= ~OPOST;
    
    tty.c_cc[VMIN] = 0;
    tty.c_cc[VTIME] = cfg.timeout_ms / 100;
    
    tcsetattr(fd, TCSANOW, &tty);
    return fd;
}
```

#### 2.1.5 SafetyMonitor - 安全监控模块

**职责**:
- 监控所有传感器健康状态
- 监控运动控制安全边界
- 检测异常情况并触发紧急停止
- 应用级命令看门狗（见下）
- 配合**硬件看门狗**（MAX6369）

**硬件看门狗（MAX6369）**:

开发板外部看门狗为 **MAX6369**，由 **J3 跳线**选择是否使能。这是独立于 Linux 的硬件复位源，
用于在系统整体卡死（含内核挂起）时强制复位，**应用层软件看门狗替代不了它**。

| 事项 | 说明 |
| --- | --- |
| 使能 | J3 选择 ON 后启用；**当前实物跳线状态待确认** |
| 喂狗者 | 必须由能判断“关键功能是否持续前进”的监督者喂狗 |
| 反例 | **禁止**用一个永远存活但业务已卡死的空循环喂狗 |
| 超时与复位行为 | 可配置超时范围与复位后的数据恢复策略均**待确认** |
| 诊断接口 | 解绑喂狗驱动会触发系统复位，**不是安全的只读健康检测**，不得放进普通诊断命令 |

喂狗条件（示例，最终值待定）：运动控制循环持续按周期推进、安全监控线程存活、
关键传感器在线、无未处理的安全故障。任一条件不满足即停止喂狗，让硬件复位。

```cpp
void SafetyMonitorLoop() {
    const auto check_period = std::chrono::milliseconds(10); // 100Hz
    auto next_check = MonotonicNow() + check_period;         // 绝对时间推进，避免累计漂移
    
    while (running_) {
        SafetyChecks checks = PerformSafetyChecks();
        
        if (!checks.all_critical_sensors_online) {
            TriggerEmergencyStop("Critical sensor offline");
        }
        
        if (!checks.within_position_limits) {
            TriggerEmergencyStop("Position limit exceeded");
        }
        
        // 命令看门狗: 500ms无命令则进入安全状态
        // 看门狗阈值随当前通道调整，切换通道时必须重新装载计时。
        // 直连 500ms；服务器中转 / G30 桥接 3s。超时层级见 通信协议规范.md §八。
        auto now = MonotonicUs();
        const uint64_t wd_us = CurrentWatchdogUs();  // 500000 / 3000000，随通道
        if (now - checks.last_command_timestamp > wd_us) {
            EnterSafeMode("Command timeout");
        }
        
        Clock::sleep_until(next_check);   // 绝对时间推进
        next_check += check_period;
    }
}
```

### 2.2 中间件层 - 实时边界与消息总线

#### 2.2.0 实时/非实时边界（最重要的一节）

RT 线程**不得**直接接触消息总线、序列化、网络或锁。跨边界只走一个
**预分配的有界无锁 SPSC 环形缓冲**：

```cpp
// 定长记录，编译期确定大小，栈/静态分配，运行期不分配
template <typename T, size_t N>
class SpscRing {
    static_assert((N & (N - 1)) == 0, "N must be power of two");
public:
    bool Push(const T& v) {                       // 仅 RT 线程调用
        const uint32_t w = w_.load(std::memory_order_relaxed);
        const uint32_t r = r_.load(std::memory_order_acquire);
        if (w - r >= N) return false;             // 满：丢弃并计数，绝不阻塞
        buf_[w & (N - 1)] = v;
        w_.store(w + 1, std::memory_order_release);
        return true;
    }
    bool Pop(T& out) { /* 仅 BoundaryThread 调用 */ }
    uint64_t DroppedCount() const { return dropped_; }
private:
    alignas(64) std::atomic<uint32_t> w_{0};
    alignas(64) std::atomic<uint32_t> r_{0};
    std::array<T, N> buf_{};
    std::atomic<uint64_t> dropped_{0};
};
```

规则：

1. `T` 必须是 POD（无指针、无 `std::string`、无容器），定长。
2. RT 线程只 `Push`；满时**丢弃并计数**，不等待、不扩容。
3. `BoundaryThread`（SCHED_OTHER，优先级 20）负责 `Pop` → 序列化 → 消息总线/网络。
4. 丢弃计数进入健康指标，超阈值告警——**不能静默丢**。
5. 订阅关系在启动阶段全部建好；RT 线程运行期不得增删订阅。

控制面（非实时）仍用消息总线做进程间通信，总线实现与 RT 线程无关。

**G30直连 (自定义TCP协议)**:
```cpp
class G30Connection {
    int socket_fd_;
    std::string g30_ip_;  // 通过光纤GbE连接
    uint16_t g30_port_;
    
public:
    bool Connect() {
        socket_fd_ = socket(AF_INET, SOCK_STREAM, 0);
        
        struct sockaddr_in addr;
        addr.sin_family = AF_INET;
        addr.sin_port = htons(g30_port_);
        inet_pton(AF_INET, g30_ip_.c_str(), &addr.sin_addr);
        
        if (connect(socket_fd_, (struct sockaddr*)&addr, sizeof(addr)) < 0) {
            return false;
        }
        
        // 设置TCP_NODELAY (低延迟)
        int flag = 1;
        setsockopt(socket_fd_, IPPROTO_TCP, TCP_NODELAY, &flag, sizeof(flag));
        
        // 设置心跳
        ConfigureTCPKeepalive(socket_fd_, 5, 3, 3); // 5s idle, 3 probes, 3s interval
        
        return true;
    }
    
    void SendMessage(const Message& msg) {
        // 简单的长度前缀协议
        uint32_t len = msg.ByteSizeLong();
        uint32_t len_be = htonl(len);
        
        send(socket_fd_, &len_be, sizeof(len_be), 0);
        
        std::string serialized = msg.SerializeAsString();
        send(socket_fd_, serialized.data(), serialized.size(), 0);
    }
    
    bool ReceiveMessage(Message& msg) {
        uint32_t len_be;
        if (recv(socket_fd_, &len_be, sizeof(len_be), MSG_WAITALL) != sizeof(len_be)) {
            return false;
        }
        
        uint32_t len = ntohl(len_be);
        if (len > MAX_MESSAGE_SIZE) {
            return false;
        }
        
        std::vector<uint8_t> buffer(len);
        if (recv(socket_fd_, buffer.data(), len, MSG_WAITALL) != len) {
            return false;
        }
        
        return msg.ParseFromArray(buffer.data(), len);
    }
};
```

```cpp
class VideoService {
    std::vector<std::unique_ptr<CameraCapture>> cameras_;
    std::vector<std::unique_ptr<H264Encoder>> encoders_;
    std::unique_ptr<StreamPublisher> publisher_;
    std::unique_ptr<VideoRecorder> recorder_;
    
public:
    void Initialize() {
        // 摄像头数量、节点、分辨率、帧率、编码码率全部来自配置——参数尚未定案，
        // 不得在代码里写死。见本节末尾“视频参数与带宽（待实测）”。

        for (const auto& cfg : cams) {
            auto camera = std::make_unique<CameraCapture>(cfg.device_node);
            camera->SetFormat(cfg.width, cfg.height, cfg.fps, cfg.pixel_format);
            cameras_.push_back(std::move(camera));
            
            auto encoder = std::make_unique<H264Encoder>();
            encoder->ConfigureRKMPP(cfg.width, cfg.height, cfg.fps, cfg.bitrate_kbps * 1000);
            encoders_.push_back(std::move(encoder));
        }
        
        publisher_ = std::make_unique<StreamPublisher>();
        // 录像根目录来自配置，指向数据盘的稳定挂载点；默认不开启录制
        recorder_ = std::make_unique<VideoRecorder>(config_.Get<std::string>("/storage/recording_root", "/data/recordings"));
    }
    
    void Start() {
        for (size_t i = 0; i < cameras_.size(); ++i) {
            std::thread([this, i]() {
                RunCameraPipeline(i);
            }).detach();
        }
    }
    
    void RunCameraPipeline(size_t cam_idx) {
        auto& camera = cameras_[cam_idx];
        auto& encoder = encoders_[cam_idx];
        
        camera->Start();
        
        while (running_) {
            // 1. 采集帧
            RawFrame frame;
            if (!camera->CaptureFrame(frame)) {
                continue;
            }
            
            // 2. 编码
            EncodedFrame encoded;
            if (encoder->Encode(frame, encoded)) {
                // 3. 推流
                publisher_->PublishFrame(cam_idx, encoded);
                
                // 4. 录制 (如果启用)
                if (recorder_->IsRecording(cam_idx)) {
                    recorder_->WriteFrame(cam_idx, encoded);
                }
            }
        }
        
        camera->Stop();
    }
};
```

```cpp
    int fd_;
    std::vector<void*> buffers_;
    
public:
    bool SetFormat(int width, int height, int fps, uint32_t pixel_format) {
        struct v4l2_format fmt = {};
        fmt.type = V4L2_BUF_TYPE_VIDEO_CAPTURE;
        fmt.fmt.pix.width = width;
        fmt.fmt.pix.height = height;
        // 像素格式由配置决定（MJPEG / H.264 / YUYV 由摄像头能力决定），不要写死。
        // 注意：YUYV 未压缩，1080p30 单路约 124MB/s，USB2.0 实际带宽（约 35–40MB/s）装不下。
        fmt.fmt.pix.pixelformat = pixel_format;
        fmt.fmt.pix.field = V4L2_FIELD_NONE;
        
        if (ioctl(fd_, VIDIOC_S_FMT, &fmt) < 0) {
            return false;
        }
        
        // 设置帧率
        struct v4l2_streamparm parm = {};
        parm.type = V4L2_BUF_TYPE_VIDEO_CAPTURE;
        parm.parm.capture.timeperframe.numerator = 1;
        parm.parm.capture.timeperframe.denominator = fps;
        ioctl(fd_, VIDIOC_S_PARM, &parm);
        
        return true;
    }
    
    bool CaptureFrame(RawFrame& frame) {
        struct v4l2_buffer buf = {};
        buf.type = V4L2_BUF_TYPE_VIDEO_CAPTURE;
        buf.memory = V4L2_MEMORY_MMAP;
        
        if (ioctl(fd_, VIDIOC_DQBUF, &buf) < 0) {
            return false;
        }
        
        frame.data = buffers_[buf.index];
        frame.size = buf.bytesused;
        frame.timestamp = buf.timestamp.tv_sec * 1000000 + buf.timestamp.tv_usec;
        
        // 归还buffer
        ioctl(fd_, VIDIOC_QBUF, &buf);
        
        return true;
    }
};
```

```cpp
        rc_cfg.rc_mode = MPP_ENC_RC_MODE_CBR;
        rc_cfg.bps_target = bitrate;
        rc_cfg.fps_in = fps;
        rc_cfg.fps_out = fps;
        
        mpp_api_->control(mpp_ctx_, MPP_ENC_SET_RC_CFG, &rc_cfg);
        
        // 配置分辨率
        MppEncPrepCfg prep_cfg;
        prep_cfg.width = width;
        prep_cfg.height = height;
        prep_cfg.format = MPP_FMT_YUV420SP;
        
        mpp_api_->control(mpp_ctx_, MPP_ENC_SET_PREP_CFG, &prep_cfg);
        
        return true;
    }
    
    bool Encode(const RawFrame& input, EncodedFrame& output) {
        // 创建输入帧
        MppFrame frame = nullptr;
        mpp_frame_init(&frame);
        mpp_frame_set_width(frame, width_);
        mpp_frame_set_height(frame, height_);
        mpp_frame_set_fmt(frame, MPP_FMT_YUV420SP);
        
        MppBuffer buf = nullptr;
        mpp_buffer_get(frame_group_, &buf, input.size);
        memcpy(mpp_buffer_get_ptr(buf), input.data, input.size);
        mpp_frame_set_buffer(frame, buf);
        
        // 送入编码器
        mpp_api_->encode_put_frame(mpp_ctx_, frame);
        
        // 获取编码后的packet
        MppPacket packet = nullptr;
        mpp_api_->encode_get_packet(mpp_ctx_, &packet);
        
        if (packet) {
            output.data = mpp_packet_get_data(packet);
            output.size = mpp_packet_get_length(packet);
            output.is_keyframe = (mpp_packet_get_flag(packet) & MPP_PACKET_FLAG_INTRA);
            output.timestamp = input.timestamp;
            
            mpp_packet_deinit(&packet);
        }
        
        mpp_frame_deinit(&frame);
        
        return output.size > 0;
    }
};
```

```cpp
class LocalStorage {
    sqlite3* db_;
    
public:
    bool Initialize(const std::string& db_path) {
        sqlite3_open(db_path.c_str(), &db_);
        
        // 创建表
        const char* schema = R"(
            CREATE TABLE IF NOT EXISTS sensor_data (
                id INTEGER PRIMARY KEY AUTOINCREMENT,
                timestamp INTEGER NOT NULL,
                sensor_type INTEGER NOT NULL,
                data BLOB NOT NULL,
                uploaded INTEGER DEFAULT 0
            );
            CREATE INDEX IF NOT EXISTS idx_timestamp ON sensor_data(timestamp);
            CREATE INDEX IF NOT EXISTS idx_uploaded ON sensor_data(uploaded);
        )";
        
        char* err = nullptr;
        sqlite3_exec(db_, schema, nullptr, nullptr, &err);
        
        return err == nullptr;
    }
    
    bool Write(const SensorData& data) {
        const char* sql = "INSERT INTO sensor_data (timestamp, sensor_type, data) VALUES (?, ?, ?)";
        
        sqlite3_stmt* stmt;
        sqlite3_prepare_v2(db_, sql, -1, &stmt, nullptr);
        
        std::string serialized = data.SerializeAsString();
        
        sqlite3_bind_int64(stmt, 1, data.timestamp_us());
        sqlite3_bind_int(stmt, 2, data.sensor_type());
        sqlite3_bind_blob(stmt, 3, serialized.data(), serialized.size(), SQLITE_TRANSIENT);
        
        int rc = sqlite3_step(stmt);
        sqlite3_finalize(stmt);
        
        return rc == SQLITE_DONE;
    }
    
    std::vector<SensorData> ReadUnuploaded(int limit) {
        const char* sql = "SELECT id, data FROM sensor_data WHERE uploaded = 0 LIMIT ?";
        
        sqlite3_stmt* stmt;
        sqlite3_prepare_v2(db_, sql, -1, &stmt, nullptr);
        sqlite3_bind_int(stmt, 1, limit);
        
        std::vector<SensorData> result;
        while (sqlite3_step(stmt) == SQLITE_ROW) {
            int64_t id = sqlite3_column_int64(stmt, 0);
            const void* blob = sqlite3_column_blob(stmt, 1);
            int blob_size = sqlite3_column_bytes(stmt, 1);
            
            SensorData data;
            data.ParseFromArray(blob, blob_size);
            result.push_back(data);
        }
        
        sqlite3_finalize(stmt);
        return result;
    }

    // 注意：ReadUnuploaded 必须把 SQLite 行 id 一并带出（例如返回
    // std::vector<std::pair<int64_t, SensorData>>），否则上传后无法回填。
    // 早期版本文档用 data.id() 取行 id，但 SensorData 这个 proto 里没有 id 字段，
    // 那段代码写不出来。
    void MarkAsUploaded(const std::vector<int64_t>& ids) {
        // 批量更新
        std::string sql = "UPDATE sensor_data SET uploaded = 1 WHERE id IN (";
        for (size_t i = 0; i < ids.size(); ++i) {
            sql += std::to_string(ids[i]);
            if (i < ids.size() - 1) sql += ",";
        }
        sql += ")";
        
        sqlite3_exec(db_, sql.c_str(), nullptr, nullptr, nullptr);
    }
    
    void DeleteOldData(int days) {
        // 需要墙上时间用于“保留 N 天”的语义；若 RTC 未同步，退化为按行数/容量裁剪。
        int64_t cutoff = WallClockUs() - days * 24 * 3600 * 1000000LL;
        
        const char* sql = "DELETE FROM sensor_data WHERE timestamp < ?";
        sqlite3_stmt* stmt;
        sqlite3_prepare_v2(db_, sql, -1, &stmt, nullptr);
        sqlite3_bind_int64(stmt, 1, cutoff);
        sqlite3_step(stmt);
        sqlite3_finalize(stmt);
        
        // 清理碎片
        sqlite3_exec(db_, "VACUUM", nullptr, nullptr, nullptr);
    }
};
```

**数据上传器**:
```cpp
class DataUploader {
    LocalStorage* storage_;
    ServerConnection* server_;
    std::queue<SensorData> upload_queue_;
    std::mutex queue_mutex_;
    
public:
    void Run() {
        while (running_) {
            // 1. 从本地数据库读取未上传数据
            auto data_batch = storage_->ReadUnuploaded(100);
            
            if (!data_batch.empty()) {
                // 2. 压缩
                std::string compressed = CompressBatch(data_batch);
                
                // 3. 上传
                if (server_->UploadSensorData(compressed)) {
                    // 4. 标记为已上传
                    std::vector<int64_t> ids;
                    for (const auto& data : data_batch) {
                        ids.push_back(data.id());
                    }
                    storage_->MarkAsUploaded(ids);
                }
            }
            
            // 5. 等待下一批
            std::this_thread::sleep_for(std::chrono::seconds(10));
        }
    }
    
    std::string CompressBatch(const std::vector<SensorData>& batch) {
        // 序列化所有数据
        SensorDataBatch batch_msg;
        for (const auto& data : batch) {
            *batch_msg.add_data() = data;
        }
        
        std::string serialized = batch_msg.SerializeAsString();
        
        // zstd压缩
        size_t compressed_size = ZSTD_compressBound(serialized.size());
        std::string compressed(compressed_size, '\0');
        
        size_t actual_size = ZSTD_compress(
            compressed.data(), compressed_size,
            serialized.data(), serialized.size(),
            3  // compression level
        );
        
        compressed.resize(actual_size);
        return compressed;
    }
};
```

#### 2.3.4 OTAManager - OTA升级管理服务

详细设计见 `OTA升级方案.md`。

**摘要（完整方案见上述文档）**:

- **整包更新**：允许停机，通过独立升级分区 + 引导切换实现；需与实机分区布局
  （`mmcblk0p1` uboot / `p3` boot / `p4` recovery / `p6` rootfs / `p8` userdata）对齐。
- **增量更新**：只热更新**独立二进制与共享库**，采用“新版本目录 + 符号链接原子切换 +
  服务重启”，**不做进程内热加载**（见 §9.1 说明）。
- **回滚**：保留上一版本目录与内核/根文件系统快照，重试计数耗尽或启动成功标记未置位时回退。
- **版本保护**：版本号单调递增，普通 OTA 拒绝降级；降级须显式授权。
- **签名与校验**：SHA256 + 公钥验签，见 `通信协议规范.md` §7.3。

**前置条件**：A/B 或独立升级分区的可回滚能力**当前实物尚不具备**（现为普通分区布局）。
在第一版中，整包更新按“停机 + 单分区替换 + 失败手工恢复”实现，待验证通过后再演进到带自动回滚的方案。

**存储契约**:

根分区实测**仅剩 4.2 GiB**，且这是 14 GiB 的 eMMC 分区。因此：

| 类别 | 位置 | 理由 |
| --- | --- | --- |
| 程序与只读资源 | `/opt/km3/`（根分区） | 只读，体积可控 |
| 配置 | `/etc/km3/`（根分区） | 小 |
| 日志、缓存、录像 | **`/data/`（数据盘）** | 写入量大，保护 eMMC |

`/data` 必须由 **UUID 稳定挂载**，不能依赖桌面的 `/run/media/...` 自动挂载路径
（实测 SSD 现挂在 `/run/media/sda1`，`userdata` 挂在 `/run/media/mmcblk0p8`）。
服务用 `RequiresMountsFor=/data` 声明依赖，挂载失败时服务不启动（而不是悄悄写到根分区）。

**时间源**:

主板有 **DS1307 RTC + CON3 电池座**。**使用不可充电 CR2032 时严禁短接 J2 充电跳线**。
系统早期启动时间可能旧于真实时间，而命令签名依赖时间窗口，因此：

- 对外记录与日志用**墙上时钟**；周期调度与超时判定用**单调时钟**（`CLOCK_MONOTONIC`）。
- 启动早期若尚未完成 NTP 同步，**不得**执行依赖时间窗口的签名校验类操作；
  由 `time.require_sync_before_signed_ops` 控制。

## 五、部署与启动

### 5.1 systemd服务配置

**km3-rt-controller.service**:
```ini
[Unit]
Description=km3 real-time controller
After=km3-can.service
Wants=km3-can.service

[Service]
Type=simple
# 指向版本化目录，部署脚本用符号链接原子切换并支持回滚
ExecStart=/opt/km3/current/km3-rt-controller
Restart=on-failure
RestartSec=1
StartLimitIntervalSec=60
StartLimitBurst=5

# 实时优先级与核心绑定（A76 大核簇）
CPUSchedulingPolicy=fifo
CPUSchedulingPriority=90
CPUAffinity=4-7

# 内存锁定与实时调度能力：只授予这个单元，而不是让程序变成 root

# 用户

Group=km3
NoNewPrivileges=true
ProtectSystem=strict
ReadWritePaths=/data

[Install]
WantedBy=multi-user.target
```

### 5.2 启动脚本

硬件初始化应交给 **systemd 单元与 udev 规则**，而不是一个手工脚本。下面只说明各项该由谁负责。
服务命名以 `系统总体架构.md` 第 9.2 节为唯一权威，本文件不再另起一套名字。

**内核模块与总线**（由 `/etc/modules-load.d/km3.conf` + udev/systemd 完成）：

```ini
# /etc/modules-load.d/km3.conf
can
can_raw
# SPI-CAN 驱动模块名以设备树 compatible 为准，需实机确认后填入，
# 不要直接写 mcp251x 之类的驱动家族名。
```

```ini
# /etc/systemd/network/10-can1.network  (can0/can1 名义速率需按现场确认)
[Match]
Name=can0 can1
[Link]
```
CAN 位速率、终端电阻、拓扑长度、bus-off 自动恢复属于**部署参数**，
建议用独立单元（如 `km3-can.service`）在启动时设置，速率从配置读取，
不要写死 500000。

**为 UI 控件设置的串口权限**用 **udev 规则按设备身份**授予，不要 `chmod 666 /dev/ttyS*`：

```
# /etc/udev/rules.d/70-km3-serial.rules
# 用厂商/序列号/物理路径匹配，避免设备枚举顺序变化后权限错配
KERNEL=="ttyS3", GROUP="km3", MODE="0660"
KERNEL=="ttyS5", GROUP="km3", MODE="0660"
KERNEL=="ttyUSB*", SUBSYSTEM=="tty", ATTRS{idVendor}=="1a86", GROUP="km3", MODE="0660"
```

业务进程以专用用户 `km3` 运行；实时调度（`CAP_SYS_NICE`）与内存锁定（`CAP_IPC_LOCK`）
通过 `AmbientCapabilities=` 单独授予**需要它们的那个单元**，不是把全部程序变成 root：

```ini
[Service]
User=km3
Group=km3
AmbientCapabilities=CAP_SYS_NICE CAP_IPC_LOCK
LimitMEMLOCK=infinity
```

**服务启动顺序**不要用 `After=network.target` 一带而过。`network.target` 只表示网络管理服务已启动，
**不代表业务目标可连接**，也不代表数据盘已挂载。需要数据盘的单元必须声明挂载依赖：

```ini
[Unit]
# 数据盘稳定挂载点（见 §2.3.5 存储契约）
RequiresMountsFor=/data
# 等待设备节点就绪，而不是等待 systemd 的“启动完成”
After=km3-can.service dev-ttyS3.device
```

### 6.3 单元测试

测试用仓库自带的零依赖 harness（`device/tests/test_harness.hpp`），**不依赖 GoogleTest**：

```cpp
#include "test_harness.hpp"
#include "km3/hal/mock_devices.hpp"
#include "km3/rt_control/motion_controller.hpp"

KM3_TEST(ClimbRopeOverLimitIsRejectedBeforeAnyFrameIsSent) {
    km3::MockRs485Device servo("rs485-1", km3::Rs485Backend::NativeSerial, {});
    km3::control::ControlBuses buses;
    buses.servo_bus = &servo;

    km3::control::ControlLimits lim;
    lim.climb_slave_addr = 1;
    lim.climb_speed_reg = 0x10;          // 模拟件的寄存器文件有限，测试用小地址
    km3::control::MotionController ctrl(buses, lim);
    KM3_REQUIRE(servo.Open().ok());

    // 越限必须**在发帧之前**被拒：把越界值交给驱动器"帮我们兜"，
    // 是把软件缺陷变成机械事故。
    KM3_CHECK(ctrl.ClimbRope(9.9F, km3::control::Direction::Up).code() ==
              km3::ErrorCode::ECommandRejected);
    KM3_CHECK_EQ(servo.SentBytes().size(), std::size_t{0});
}

KM3_TEST_MAIN()
```

`KM3_TEST` 只注册不执行。`KM3_REQUIRE` 失败即中止该用例（否则失败后继续执行会解引用
空对象，把断言失败变成段错误）；`KM3_CHECK` 记录失败并继续。消毒器用
`-DKM3_SANITIZER=address|thread` 切换，两者互斥。

> 早期文档此处给的是 GoogleTest 示例——那只是设想，仓库从未引入 gtest，
> 留着就与真实测试形成第二份真相，已删除。

## 七、性能优化建议

### 7.1 CPU 绑定与实时环境

**已实现**，见 `device/include/km3/rt_util.hpp`：`BindCurrentThreadToCpus` /
`SetCurrentThreadRealtime` / `LockMemory`，由 `test_clock.cpp` 覆盖。
RT 线程绑 CPU4-7（A76），非 RT 线程绑 CPU0-3（A55）。
实测依据：`policy0 = cpu0-3 @1296MHz (A55)`，`policy4/policy6 = cpu4-7 @1608MHz (A76)`。
实机结果与结论边界见 `实测基线.md §七`。

> 早期文档在此处放了一段手写 `pthread_setaffinity_np` 示例，已删除：
> 它是与头文件并列的第二份真相，且不含 `mlockall` 顺序、返回值处理与失败日志。

### 7.2 内存锁定

同样已实现（`LockMemory`，内部 `mlockall(MCL_CURRENT | MCL_FUTURE)`）。

**不要照抄早期文档里“用大数组预热栈”的写法**：

```cpp
unsigned char dummy[8 * 1024 * 1024];   // 8 MB 栈数组
```

默认线程栈就是 8 MB，这一句直接撑爆栈并 SIGSEGV。预热也不需要；
若确实要预留栈，应在建线程时用 `pthread_attr_setstacksize` 显式指定。

### 7.3 零拷贝技术

```cpp
// 使用共享内存传递大数据
class SharedMemoryBuffer {
    int shm_fd_;
    void* ptr_;
    size_t size_;
    
public:
    void Create(const std::string& name, size_t size) {
        shm_fd_ = shm_open(name.c_str(), O_CREAT | O_RDWR, 0666);
        ftruncate(shm_fd_, size);
        ptr_ = mmap(nullptr, size, PROT_READ | PROT_WRITE, MAP_SHARED, shm_fd_, 0);
        size_ = size;
    }
    
    void* GetPointer() { return ptr_; }
};

// 视频帧在共享内存中传递，避免拷贝
```

```cpp
public:
    void RecordLoopTime(uint64_t loop_time_us) {
        if (loop_time_us > expected_loop_time_us_ * 1.1) {
```

## 九、后续扩展

### 9.1 关于“插件 / 热加载”——不做

早期版本设想过一个 dlopen 插件系统用于“增量热更新”。**该设计取消**，原因：

- 本项目硬件确定，没有第三方扩展需求，插件化只带来 ABI 稳定性负担。
- 进程内 `dlopen` 热替换在实时进程里有明确风险（对象生命周期、锁、已注册的回调、
  已分配缓冲），收益远低于成本。

**增量更新改用更简单的做法**：每个模块是独立二进制，按版本目录存放，
用符号链接原子切换 + 服务重启。这样更新与回滚都只是切换链接，
不需要在进程内做任何动态加载。

### 9.2 云端监控与诊断

- 实时性能指标上报
- 远程日志查看
- 远程调试接口 (gdbserver)

### 9.3 多机器人协同

清单 B04 要求“设备发现、编号与在线管理”，因此**设备发现是正式需求，不是后续扩展**：

- 单机阶段的“发现”指：设备首次上线如何被服务器登记、如何分配唯一编号、
  证书 CN 与编号如何绑定、线下贴标与线上 ID 如何对应。
- 多机阶段才扩展到机器人间通信与分布式调度。

编号规则、发现流程与证书绑定的完整定义见 `服务器端程序架构.md` 的设备管理章节。
