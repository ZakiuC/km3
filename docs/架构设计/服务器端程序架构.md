# 服务器端程序架构

运行环境：阿里云 VPS，Linux，**原生部署**（systemd + nginx）。语言：C++17。

本文件描述服务器端的模块边界、数据模型、接口契约与部署拓扑。
实现细节（超过 15 行的代码）不在本文档，见代码仓库。

## 一、总体设计

### 1.1 形态：单进程模块化单体

单二进制 `km3-server`，内部按模块划分。当前规模（个位数用户、个位数设备）下，
拆微服务只会增加运维与排障成本。

```
km3-server (单进程)
├── http      HTTP/WebSocket 接入（Boost.Beast + Asio）
├── user      用户、会话票据、权限
├── device    设备注册、会话表、命令队列、心跳
├── data      传感器数据落库与查询（PostgreSQL 分区表）
├── log       日志摄入与检索
├── ota       固件元数据、分发、部署状态机
└── bus        进程内 topic 事件总线（前端推送用）
```

**不引入**：Docker、Redis、InfluxDB、RabbitMQ、NATS、gRPC、ORM。

### 1.2 技术选型与理由

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 网络 | Boost.Asio + Boost.Beast | 一次覆盖 HTTP、WebSocket、TLS、TCP、定时器，避免多套客户端库各自处理连接生命周期 |
| JSON | nlohmann/json | 与设备端一致，便于 canonical 化签名 |
| 序列化 | Protobuf（设备↔G30 二进制帧）；对外 API/WS 用 JSON | 见协议规范 §一 |
| 数据库 | PostgreSQL 16（本机安装） | 关系 + 时序（分区表）+ 会话，**单库**，事务一致性只交给一个组件 |
| 连接 | libpqxx | 不引入 ORM；单项目里 ORM 是负资产 |
| 加密 | libsodium（Ed25519）、OpenSSL（TLS） | 签名/验签/常量时间比较/随机数在一个 API 正确的库里 |
| 日志 | spdlog | 与设备端一致 |
| TLS 终止与固件分发 | nginx | `sendfile` 分发固件更省事；也便于限流 |

### 1.3 与设备端的语言统一

三端同为 C++（前端 Kotlin）的核心收益：**同一份协议定义、同一份签名与验签实现、
同一份 canonical JSON 规则、同一套错误码**。这是减少三端行为漂移的主要手段。

**风险（如实记录）**：C++ 的迭代-编译-调试循环比 Go 慢，`asio` 异步回调的错误处理
样板量大，模板错误信息会降低 agent 一次写对的概率。缓解手段：
①协议、数据结构、接口签名先以头文件固定，让 agent 只填实现；
②所有跨回调对象用 `shared_from_this`，设备会话表用单线程 `strand` 保护；
③CI 必跑 ASan/UBSan/TSan。
若服务端进度落后设备端超过 4 周，可在评审时改为 Go 单二进制（**此决策点由用户拍板**）。

## 二、数据模型（PostgreSQL）

### 2.1 表结构

**users** — 用户与角色：

```sql
CREATE TABLE users (
    id            BIGSERIAL PRIMARY KEY,
    username      VARCHAR(50) UNIQUE NOT NULL,
    email         VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    role          VARCHAR(20) NOT NULL DEFAULT 'operator',
    status        VARCHAR(20) NOT NULL DEFAULT 'active',
    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    last_login_at TIMESTAMPTZ
);
```

**sessions** — 服务端会话票据（**替代 JWT**，支持即时吊销）：

```sql
CREATE TABLE sessions (
    session_id  VARCHAR(64) PRIMARY KEY,
    user_id     BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    expires_at  TIMESTAMPTZ NOT NULL,
    revoked_at  TIMESTAMPTZ,
    client_ip   INET
);
CREATE INDEX idx_sessions_user ON sessions(user_id);
```

**user_invitations** — 邀请：

```sql
CREATE TABLE user_invitations (
    id          BIGSERIAL PRIMARY KEY,
    email       VARCHAR(255) NOT NULL,
    role        VARCHAR(20) NOT NULL,
    token       VARCHAR(64) UNIQUE NOT NULL,
    invited_by  BIGINT NOT NULL REFERENCES users(id),
    expires_at  TIMESTAMPTZ NOT NULL,
    accepted_at TIMESTAMPTZ,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

邀请的投递方式与 token 生命周期见 §4.3。

**environments** — 环境（测试 / 演示 / 生产）：

```sql
CREATE TABLE environments (
    id    SMALLSERIAL PRIMARY KEY,
    code  VARCHAR(20) UNIQUE NOT NULL,   -- 'test' | 'demo' | 'prod'
    name  VARCHAR(50) NOT NULL
);
```

**devices** — 设备：

```sql
CREATE TABLE devices (
    id               BIGSERIAL PRIMARY KEY,
    device_id        VARCHAR(50) UNIQUE NOT NULL,
    name             VARCHAR(100) NOT NULL,
    model            VARCHAR(50) NOT NULL,
    env_id           SMALLINT NOT NULL REFERENCES environments(id),
    firmware_version VARCHAR(20),
    status           VARCHAR(20) NOT NULL DEFAULT 'offline',
    cert_fingerprint VARCHAR(64),        -- Ed25519 公钥指纹，与设备编号绑定
    last_seen_at     TIMESTAMPTZ,
    location         VARCHAR(255),
    created_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at       TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_devices_env ON devices(env_id);
CREATE INDEX idx_devices_status ON devices(status);
```

`env_id` 是**必须的**：演示与生产必须隔离，否则演示数据会污染生产、生产固件会被推到演示机。

**device_public_keys** — 设备公钥表（支持轮换）：

```sql
CREATE TABLE device_public_keys (
    device_id   VARCHAR(50) NOT NULL,
    public_key  BYTEA NOT NULL,          -- Ed25519 32 字节
    fingerprint VARCHAR(64) NOT NULL,
    valid_from  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    revoked_at  TIMESTAMPTZ,
    PRIMARY KEY (device_id, fingerprint)
);
```

**device_commands** — 命令与状态机：

```sql
CREATE TABLE device_commands (
    id              BIGSERIAL PRIMARY KEY,
    command_id      UUID NOT NULL UNIQUE,      -- 发起方生成的 UUIDv7，对外唯一标识
    device_id       VARCHAR(50) NOT NULL,
    user_id         BIGINT REFERENCES users(id),
    command_type    VARCHAR(50) NOT NULL,
    command_data    JSONB NOT NULL,
    priority        SMALLINT NOT NULL DEFAULT 5,
    status          VARCHAR(20) NOT NULL DEFAULT 'pending',
    -- pending|queued|sent|acked|completed|failed|timeout|cancelled
    timeout_at      TIMESTAMPTZ NOT NULL,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    sent_at         TIMESTAMPTZ,
    acked_at        TIMESTAMPTZ,
    completed_at    TIMESTAMPTZ,
    result          JSONB,
    error_code      VARCHAR(40),
    error_message   TEXT
);
CREATE INDEX idx_cmd_device_status ON device_commands(device_id, status);
CREATE INDEX idx_cmd_timeout ON device_commands(timeout_at) WHERE status IN ('pending','queued','sent','acked');
```

**command_dedup** — 幂等去重（设备侧与服务侧各一份语义）：

```sql
CREATE TABLE command_dedup (
    device_id   VARCHAR(50) NOT NULL,
    command_id  UUID NOT NULL,
    applied_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    PRIMARY KEY (device_id, command_id)
);
```

**firmware** — 固件：

```sql
CREATE TABLE firmware (
    id            BIGSERIAL PRIMARY KEY,
    version       VARCHAR(20) NOT NULL,
    model         VARCHAR(50) NOT NULL,
    env_id        SMALLINT NOT NULL REFERENCES environments(id),
    file_path     VARCHAR(500) NOT NULL,
    file_size     BIGINT NOT NULL,
    file_hash     VARCHAR(64) NOT NULL,      -- SHA256
    signature     BYTEA NOT NULL,            -- Ed25519，离线签名
    changelog     TEXT,
    is_stable     BOOLEAN NOT NULL DEFAULT false,
    min_version   VARCHAR(20),
    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    created_by    BIGINT REFERENCES users(id),
    UNIQUE(version, model, env_id)
);
```

**ota_deployments** — OTA 部署：

```sql
CREATE TABLE ota_deployments (
    id               BIGSERIAL PRIMARY KEY,
    firmware_id      BIGINT NOT NULL REFERENCES firmware(id),
    device_id        VARCHAR(50) NOT NULL,
    status           VARCHAR(20) NOT NULL DEFAULT 'pending',
    progress         SMALLINT NOT NULL DEFAULT 0,
    prev_version     VARCHAR(20),            -- 部署前版本，回滚目标以此为准
    kind             VARCHAR(20) NOT NULL,   -- 'full' | 'incremental'
    created_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    started_at       TIMESTAMPTZ,
    completed_at     TIMESTAMPTZ,
    error_code       VARCHAR(40),
    error_message    TEXT
);
```

`prev_version` 是新增字段：**回滚目标必须来自设备侧记录的上一版本**，
不能由服务端在部署时用「设备当前版本」推导，否则回滚会覆盖自身形成不可逆状态。

**runtime_configs** — 运行配置：

```sql
CREATE TABLE runtime_configs (
    id           BIGSERIAL PRIMARY KEY,
    device_id    VARCHAR(50) NOT NULL,
    config_key   VARCHAR(100) NOT NULL,
    config_value JSONB NOT NULL,
    version      INTEGER NOT NULL DEFAULT 1,
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_by   BIGINT REFERENCES users(id),
    UNIQUE(device_id, config_key)
);
```

配置项必须有 **schema 白名单**（键、类型、取值范围、可编辑角色），见 §4.5。

**device_logs** — 日志中心：

```sql
CREATE TABLE device_logs (
    id          BIGSERIAL PRIMARY KEY,
    device_id   VARCHAR(50) NOT NULL,
    ts          TIMESTAMPTZ NOT NULL,
    level       SMALLINT NOT NULL,            -- trace..fatal
    module      VARCHAR(40) NOT NULL,
    message     TEXT NOT NULL,
    fields      JSONB,
    trace_id    UUID
);
CREATE INDEX idx_logs_device_ts ON device_logs(device_id, ts DESC);
CREATE INDEX idx_logs_level ON device_logs(level) WHERE level >= 4;
```

**audit_logs** — 操作审计（谁下了什么命令、谁推了固件）：

```sql
CREATE TABLE audit_logs (
    id         BIGSERIAL PRIMARY KEY,
    user_id    BIGINT REFERENCES users(id),
    action     VARCHAR(50) NOT NULL,
    target     VARCHAR(120),
    detail     JSONB,
    ts         TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### 2.2 时序数据

传感器数据**不引入 InfluxDB**，用 PostgreSQL 按月分区表承载。当前量级
（降频上报，单机日均约数十万行）单库绰绰有余；将来真需要时可加 TimescaleDB 扩展。

```sql
CREATE TABLE sensor_data (
    device_id     VARCHAR(50) NOT NULL,
    ts            TIMESTAMPTZ NOT NULL,
    sensor_type   VARCHAR(40) NOT NULL,
    sensor_id     VARCHAR(40),
    value_num     DOUBLE PRECISION,
    value_json    JSONB,
    quality       SMALLINT,
    schema_version SMALLINT NOT NULL DEFAULT 1
) PARTITION BY RANGE (ts);
```

`schema_version` 是硬约束：本地缓存保留 30 天，跨版本回滚时旧固件会读到新固件写的数据。

## 三、接口

### 3.1 REST（/api/v1）

统一响应包：`{ "success": bool, "data": ..., "error": {"code","message"}, "ts": <RFC3339> }`。

| 组 | 端点 |
| --- | --- |
| 认证 | `POST /auth/login`、`POST /auth/logout`、`POST /auth/register`(邀请码)、`POST /auth/refresh` |
| 环境 | `GET /environments` — 管理端填充环境切换器用；**仅返回调用者可见的环境** |
| 用户 | `GET/POST /users`、`GET/PUT/DELETE /users/:id`、`POST /users/invite`、`GET /users/invitations` |
| 设备 | `GET/POST /devices`、`GET/PUT/DELETE /devices/:id`、`GET /devices/:id/status` |
| 命令 | `POST /devices/:id/commands`、`GET /devices/:id/commands`、`GET /commands/:id`、`DELETE /commands/:id` |
| 配置 | `GET /devices/:id/config`、`GET /devices/:id/config/schema`、`PUT /devices/:id/config` |
| OTA | `GET/POST /firmware`、`GET /firmware/:id`、`POST /firmware/:id/deploy`、`GET /devices/:id/ota`、`POST /devices/:id/ota/cancel` |
| 数据 | `GET /devices/:id/sensors`、`GET /devices/:id/sensors/:type/history` |
| 日志 | `GET /devices/:id/logs`、`GET /logs`（跨设备检索） |
| 分析 | `GET /analytics/overview`、`GET /analytics/workhours`、`GET /analytics/reports` |
| 运维 | `GET /healthz`、`GET /readyz` |

**列表接口统一支持** `?page=&size=&sort=&order=`，默认 `page=1&size=50`。

**健康检查分级**：`/healthz` 只报进程存活（永远 200）；`/readyz` 才检查
数据库可写与设备通道可服务。**时序写入失败只降级，不摘除主服务**——
否则中间件抖动会让命令通道整体 503。

### 3.2 WebSocket

| 端点 | 认证 |
| --- | --- |
| `/api/v1/device/ws` | 握手时 Ed25519 挑战应答（§4.2） |
| `/api/v1/frontend/ws` | 握手时校验会话票据；WS 建立后不重复认证 |

会话失效时服务器主动关闭连接并带上 close code（见协议规范 §四）。

订阅与授权：订阅 `device.<id>.*` 时**必须校验该设备是否属于该用户可管范围**，
不能只验「已登录」。当前实现在此处的缺口已修正。

## 四、核心服务

### 4.1 命令准入、排队与结果跟踪

状态机：

```
pending ──入队──► queued ──下发──► sent ──ACK──► acked ──RESULT──► completed
   │                │               │              │
   └────────────────┴───────────────┴──────────────┴──► timeout / cancelled
```

关键修正（相对早期版本）：

1. **设备离线不再直接丢弃命令**。清单 B05 要求「排队」：设备离线时命令进入 `queued`，
   等待设备上线后下发，直到 `timeout_at` 才转 `timeout`。只有 `priority=1` 的实时命令
   会因离线而立即失败。
2. **超时改为数据库驱动**。写入 `timeout_at = now() + timeout`，由一个每秒扫描的
   维护任务批量置 `timeout`。**不再为每条命令起一个 goroutine sleep**——
   那些 goroutine 在服务重启后全部丢失，会让命令永远停在 `sent`。
3. **`command_id` 由发起方生成 UUIDv7**（含时间前缀、可排序），数据库 `id` 只作内部索引。
   设备 ACK/RESULT 一律回 `command_id`，不涉及数据库主键。
4. **优先级队列**：`priority` 1..5（1 最高）。`queue` 按 `(priority, created_at)` 出队。
   紧急停止不走此队列（见 §4.6）。
5. **幂等**：同一 `command_id` 重复到达，设备按 `command_dedup` 去重，
   回放上次结果；服务端也做重复受理检查。双通道切换导致的重复下发不会重复执行。
6. **下发 payload 必须包含** `command_type`、`priority`、`timeout_ms`，
   不能只发 `params`（设备无法判断这是爬升还是配置更新）。

### 4.2 设备认证与发现

**挑战应答**（替代 mTLS + CA + CRL + 证书轮换三套机制）：

1. 设备建立 TLS（标准服务端证书）后发送 `hello {device_id}`。
2. 服务器回 `challenge {nonce, ts}`。
3. 设备回 `auth {device_id, nonce, ts, sig = Ed25519(device_key, device_id‖nonce‖ts)}`。
4. 服务器查 `device_public_keys` 验签；指纹未注册则拒绝并记审计。

**首次上线（编号与发现）**——明确先后顺序，消除鸡生蛋：

```
1. 生产/部署时在服务器创建设备记录，分配 device_id（规则见下），生成初始 Ed25519 密钥对
2. 私钥写入设备 /etc/km3/device.key（0600），公钥存入 device_public_keys
3. 设备首次上线即按上述挑战应答认证，无需另行「注册」
4. 线下贴标（二维码/铭牌）与 device_id 一一对应，由部署流程生成并打印
```

**编号规则**：`<前缀>-<env>-<seq>`。三段均不为空，用 `-` 连接：

| 段 | 含义 | 取值 |
| --- | --- | --- |
| `<前缀>` | 设备标识前缀，通常取设备型号；本项目取项目名 `km3` | 小写字母与数字 |
| `<env>` | 环境 | **必须是 `environments.code` 的取值**：`test` / `demo` / `prod` |
| `<seq>` | 同环境内的序号，阿拉伯数字 | 由服务器分配，`devices.device_id UNIQUE` 保证唯一 |

例：`km3-test-001`（本项目第一块测试板）、`km3-prod-001`（首个生产设备）。

**`env` 段不是自由文本**：它决定这台设备出现在哪个环境的后台里，
写错的表现是「设备在列表里但谁也连不上」——查起来要跨服务器、管理端、前端三端。
因此 `env` 的取值域与 `server/migrations/0001_init.sql` 的 `environments` 种子
**必须一致**，且由设备端 `ValidateConfig` 的规则 8 在加载期强制。

**`robot-001` 之类的字面量不得散落在**协议示例、InfluxDB tag、前端主题拼接里，
一律由配置注入。

**在线管理**：心跳 5s（应用层），30s 无心跳判离线；在线状态放进程内会话表，
同时落 `devices.last_seen_at`。会话表用单线程 `strand` 保护。

### 4.3 用户与邀请

- 密码哈希：libsodium 的 `crypto_pwhash`（Argon2id）。
- 会话：随机 `session_id` 存 `sessions` 表。**不用 JWT**——
  并发量极小，查库成本可忽略，却换来最直接的登出与禁用语义。

**会话票据的传输载体（此前未定义，现补）**：

| 客户端 | 载体 | 理由 |
| --- | --- | --- |
| 管理端 Web | `HttpOnly` + `Secure` + `SameSite=Strict` Cookie | 管理端要渲染日志与用户输入的自由文本，票据放在脚本可读处，一次 XSS 即等于票据泄露。载体是 Cookie 时，WebSocket 同源握手也会自动携带，实时通道无需另想办法传票据 |
| Android 控制台 | 请求头（`Authorization: Bearer <ticket>`） | 原生客户端无浏览器同源模型，无 XSS 面；票据存 Android 加密存储 |

Cookie 方案要求管理端与 `/api/v1` **同源部署**（nginx 同域），因此不需要 CORS。
同时必须做 CSRF 防护：`SameSite=Strict` 不足以覆盖同站子域场景，
所有非幂等方法需回填 `X-CSRF-Token` 做双提交校验。
详见 `管理端Web程序架构.md` §四。
- 邀请：`POST /users/invite` 生成一次性 token（`expires_at` 默认 72h），
  **投递方式为返回邀请链接**（`https://<host>/invite?token=...`），由管理员转达；
  第一版不接入邮件服务。token 使用一次即写 `accepted_at`，后续请求拒绝。
- 新增错误码：`EINVITE_EXPIRED`、`EINVITE_USED`、`EEMAIL_EXISTS`、`ETOKEN_INVALID`。

### 4.4 权限矩阵

四级角色。权限矩阵是本节的权威定义：

| 能力 | superadmin | admin | operator | viewer |
| --- | --- | --- | --- | --- |
| 查看设备状态与传感器 | ✓ | ✓ | ✓ | ✓ |
| 下发运动/控制命令 | ✓ | ✓ | ✓ | ✗ |
| 查看视频 | ✓ | ✓ | ✓ | ✓ |
| 修改运行配置 | ✓ | ✓ | ✓ (受限项) | ✗ |
| 上传/分发固件 | ✓ | ✓ | ✗ | ✗ |
| 用户与邀请管理 | ✓ | ✓ | ✗ | ✗ |
| 查看审计日志 | ✓ | ✓ | ✗ | ✗ |
| 隐藏功能/调试入口 | ✓ | ✓ | ✗ | ✗ |
| 跨环境切换 | ✓ | ✗ | ✗ | ✗ |

实现要求：`has_permission(role, action)` 是**单一函数**，矩阵是数据而非散落的 `if`。
早期文档只调用了 `hasPermission` 却未定义，属编译不过的缺陷。

### 4.5 运行配置管理

- `GET /devices/:id/config/schema` 返回可配置项清单：`{key, type, range, editable_by, current}`。
  **前端配置面板据此动态渲染**，避免每加一个参数就改 App 发版。
- `PUT` 前按 schema 校验类型与范围，拒绝写未知键（对应 `EINVALID_CONFIG`）。
- 配置下发后需等设备 `ConfigResponse` 确认闭环，写入 `runtime_configs.version` 做乐观锁；
  版本冲突返回 `ECONFIG_CONFLICT`。
- 写坏的安全相关参数（如 `climb_speed_max_mps`）能直接下发到 RT 进程，
  因此**校验必须发生在服务端与设备端两侧**。

### 4.6 紧急停止专线

紧急停止是安全关键路径，**不复用普通命令队列**：

- 独立消息类型 `estop`，允许插队，不受队列长度限制。
- 服务器侧**先发后记**：直接 `send`，失败再补偿写审计，不做前置落库与在线检查。
- 设备端有独立处理路径，不经命令队列。
- 协议规范 §八定义其超时与优先级。

### 4.7 日志中心

- **摄入**：设备通过 WebSocket `log` 消息批量上报（协议规范 §三）；
  前端通过 `POST /logs/frontend` 上送「前端采集」的客户端日志与页面操作记录。
- 存储：`device_logs`，按 `(device_id, ts)` 索引；保留期默认 30 天，超期归档或删除。
- 查询：`GET /devices/:id/logs`（单设备）与 `GET /logs`（跨设备，管理端用），
  支持 `level>=`、`module=`、时间范围。
- **实时更新**：前端订阅 `log.<device_id>` topic 获取实时流。

### 4.8 OTA 服务

- 固件**离线签名**：开发机持 Ed25519 私钥，产出 `firmware.bin + .sig + manifest.json`；
  服务器只分发，**不持私钥**（服务器被入侵不等于能签发固件）。
- 部署：`POST /firmware/:id/deploy` 前检查 `env_id` 一致与环境隔离、`min_version` 兼容。
- 进度：设备通过 `ota_progress` 消息上报（协议规范新增该消息类型），
  服务端更新 `ota_deployments.progress`，并通过 `ota.<device_id>` topic 推给前端。
- 回滚：目标为 `ota_deployments.prev_version`（来自设备侧记录），
  **降级需管理员携带显式授权标志并记审计**；`Rollback` 与「版本单调递增」不是互斥规则，
  而是「默认拒绝降级 + 显式授权可降级」。
- 详见 `OTA升级方案.md`。


### 5.3 systemd 单元

```ini
[Unit]
Description=km3 backend
After=network-online.target postgresql.service
Wants=network-online.target
RequiresMountsFor=/data

[Service]
Type=simple
User=km3
Group=km3
ExecStart=/opt/km3-server/current/km3-server -config /etc/km3-server/config.json
Restart=on-failure
RestartSec=3
# 避免无限快速重启掩盖配置错误
StartLimitIntervalSec=60
StartLimitBurst=5
NoNewPrivileges=true
ProtectSystem=strict
ReadWritePaths=/data

[Install]
WantedBy=multi-user.target
```

### 5.4 部署脚本（原生化）

`tools/deploy_server.sh`：构建 → `rsync` 二进制到新的 `releases/<version>/` →
`systemctl restart km3-server` → 健康检查 `/readyz` → **失败则切回上一版本目录并重启**。

## 六、安全

详见 `通信协议规范.md` §七。服务器侧要点：

- TLS 1.3，服务端证书；**不做 mTLS**（设备认证用挑战应答）。
- 命令签名在**设备端校验**，服务器不是唯一验签点。
- 固件签名私钥离线。
- 所有写操作记 `audit_logs`。
- 不以 root 运行，`NoNewPrivileges` + `ProtectSystem=strict`。

### 4.9 工时统计（口径需先定，当前仅为提案）

`work_hours` 汇总表本身不足以支撑功能——**必须先定「这些行由谁写入」**。提案：

| 类别 | 判定来源 | 规则 |
| --- | --- | --- |
| climb | 设备 `motion_status` 中爬升子系统的运行时长 | 由设备按周期累计上报 |
| inspect | 作业模式下的有效工作时长 | 按作业会话统计 |
| idle | 在线但无作业动作的时长 | 由会话与状态推导 |
| maintenance | 人工填写 | 需操作员权限，记审计 |

**同时需要操作员维度**（表当前只有 `device_id + date + category`），
否则算不出「谁在什么时间干了多少」。

```sql
ALTER TABLE work_hours ADD COLUMN user_id BIGINT REFERENCES users(id);
```

**口径与维度需用户确认后再实现**，当前不做无依据的聚合。
