## 二、CPU 拓扑（重要更正）

`/sys/devices/system/cpu/cpufreq/policy*` 实测：

| policy | related_cpus | 最高频率 | 对应簇 |
| --- | --- | ---: | --- |
| policy0 | 0 1 2 3 | 1296000 kHz | **Cortex-A55** |
| policy4 | 4 5 | 1608000 kHz | **Cortex-A76** |
| policy6 | 6 7 | 1608000 kHz | **Cortex-A76** |

结论：**CPU0–3 是 A55，CPU4–7 是 A76。**

架构文档把实时控制线程绑定到 CPU0–3 并称其为 A76 —— **该绑定与命名都需更正**。
正确做法是：实时控制放在 **CPU4–7（A76）**，管理/网络/日志等非实时服务放在 **CPU0–3（A55）**。

旁证：主板技术资料的 cyclictest 结果中，满载最坏唤醒延迟 CPU4–7 为 10/15/12/10 µs，
CPU0–3 为 80/23/38/66 µs，与 A76 更适合实时任务一致。

三簇调频均为 `performance`。当前内核命令行**未见 `isolcpus=`**，即尚未做 CPU 隔离。

## 七、实时性首次实测（2026-10-13 17:05）

这是**第一次在实机上以实时权限运行** km3 自己的周期循环（此前主机运行全部降级为
`SCHED_OTHER`，因为非特权环境下 `mlockall` / `SCHED_FIFO` 返回 `EPERM`）。

### 测试条件

| 项 | 值 |
| --- | --- |
| 程序 | `km3-rt-controller`（骨架，见 `device/src/apps/rt-controller/main.cpp`） |
| 周期 | 1000 µs（1 kHz），绝对时间推进 |
| 时长 / 周期数 | 10 秒 / 10000 个周期 |
| 调度 | `SCHED_FIFO` 优先级 90 |
| 亲和性 | CPU 4–7（A76 大核簇），实际落在 **CPU7** |
| 内存 | `mlockall(MCL_CURRENT \| MCL_FUTURE)` 成功 |
| 内核 | `6.1.141-rt36-00076-g8c1479751b6e-dirty`，`/sys/kernel/realtime` = 1 |
| 调频 | 三个 policy 均为 `performance` |
| CPU 隔离 | **未配置**（`/sys/devices/system/cpu/isolated` 为空） |
| 起始负载 | loadavg 1.34 / 0.46 / 0.25 |

### 结果

| 指标 | 值 |
| --- | ---: |
| ticks | 10000 |
| overruns（被吃掉的周期） | **0** |
| 实质性迟到（> 阈值 100 µs） | **0** |
| **最大迟到量** | **1 µs** |
| 环形缓冲丢弃 | **0** |

### 这证明了什么

- 在 **RT 内核 + `SCHED_FIFO` + 内存锁定 + 大核绑定** 的组合下，本程序的周期唤醒抖动
  在 1 kHz 下为 **1 µs 量级**，且 10 秒内无一周期被吃掉。
- `rt_util` 的实时设置路径（取时钟 → 锁内存 → 预触栈 → 绑核 → 提优先级）在实机可用，
  顺序正确（先绑核后提权）。
- 时基实现（单调时钟 + 绝对推进 + 迟到阈值统计）在实机上行为正确。

### 这**没有**证明什么（不得当作端到端实时性结论）

1. **循环体是空的**：当前只做一次 `memcpy` 级别的环形缓冲写入，
   没有采样、没有控制律、没有总线收发。真实控制回路的**执行时间**完全未测。
2. **无业务负载**：未接摄像头、未接 USB-RS485 / USB-CAN 模块、无 WiFi 流量、无 SSD 写入。
   资料明确要求「实时验收必须在启用这些实际业务负载的情况下进行」。
3. **无 CPU 隔离**：`isolcpus=` 未配置，中断仍可落到大核上。
   当前的 1 µs 是"运气不错"，不构成对中断干扰的免疫证明。
4. **未测端到端控制响应**：从命令到机械动作的链路包含总线帧时间、驱动器解析时间、
   机械延迟，与线程唤醒抖动不是同一个量。
5. **单次 10 秒样本**：不是长稳测试。资料中的厂测为 12 小时。

## 八、对架构文档的直接结论

1. **CPU 绑定纠正**：实时控制 → CPU4–7（A76）；非实时服务 → CPU0–3（A55）。
   文档现有表述相反，必须修正。
2. **CPU 隔离**需在内核命令行（`isolcpus=`）与 IRQ 亲和性层面完成，属平台层，
   不是应用线程自行设置即可。文档需把这一前置条件写清。
3. **存储契约**：不得使用根分区；需为 SSD/userdata 配置 UUID 稳定挂载，
   并在 systemd 中声明依赖。文档需补此条。
4. **网络带宽**：eth0 现为百兆，若设计假设千兆需实测确认。
5. **视频**：6 路摄像头当前未接入，所有关于分辨率/帧率/路数的设计
   必须标注为**待实测**，不可作为既定能力。
6. **总线**：CAN 与 USB-RS485/USB-CAN 模块当前均未接入，
   相关总线层需先按接口契约实现，待硬件到位后联调。
