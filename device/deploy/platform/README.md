# 实时平台配置（尚未应用）

`docs/架构设计/系统总体架构.md §七` 与 `实测基线.md §二` 记录了这条约束：

> CPU 隔离须在平台层完成：`isolcpus` 内核命令行 + IRQ 亲和性。当前**未配置**。

在此之前，内核命令行里没有 `isolcpus=`，所有中断都会落到全部 8 个核上。
仅靠线程 `CPUAffinity` 只能限制线程**往哪跑**，**不能阻止中断打断它**——
所以 1ms 周期与 ≤5ms 响应的目标目前没有平台层支撑。

本目录把这条约束落成可审查、可回滚的配置。

## 核心划分

| 用途 | 核 | 依据 |
| --- | --- | --- |
| 实时控制 | **CPU4–7（Cortex-A76，≤1608MHz）** | `实测基线.md §二`；厂测满载最坏唤醒延迟 10/15/12/10 µs |
| 普通负载 | CPU0–3（Cortex-A55，≤1296MHz） | 同上；满载最坏 80/23/38/66 µs |

注意这与早期文档相反（早期把实时绑到 CPU0–3 并称其为 A76），已更正。

## 三项配置

| 配置 | 作用 |
| --- | --- |
| `isolcpus=4-7` | 把大核从通用调度器摘出，只有显式设了亲和性的任务才会跑在上面 |
| `nohz_full=4-7` | 大核进入无时钟中断模式，减少周期性 tick 干扰 |
| `rcu_nocbs=4-7` | 把 RCU 回调搬离大核，避免软中断打断实时线程 |
| IRQ 亲和性 | 把所有中断压到 CPU0–3（见 `irq-affinity.sh`） |

## 应用步骤（**待验证，勿直接上生产**）

```sh
# 1) 备份当前内核命令行
cat /proc/cmdline

# 2) 把 cmdline-isolcpus.txt 的参数追加到现有命令行
#    注意：是"追加"，不要整行覆盖掉 root=/dev/mmcblk0p6 等既有参数
#    普通分区布局下该参数位于 /boot 或 U-Boot 环境，按实际布局修改

# 3) 重启后确认
cat /proc/cmdline | tr ' ' '\n' | grep -E 'isolcpus|nohz_full|rcu_nocbs'
ls /sys/devices/system/cpu/isolated      # 应显示 4-7

# 4) 设置 IRQ 亲和性
sudo bash device/deploy/platform/irq-affinity.sh

# 5) 基线对比（关键）
cyclictest -m -Sp99 -i1000 -h800 -D12h -q    # 应用前后各跑一次，比对最坏值
```

## 风险

- 本板 RT 内核与 WiFi 驱动修复（`8188eu`）是脆弱组合，改动引导参数后**必须重新验证 WiFi 关联与重启自动连接**。
- 隔离大核后，若某个服务被错误地默认调度到 4–7，会表现为启动缓慢或行为异常。
- **未验证前不得写入文档当作已有能力。** 验收要求见 `系统总体架构.md §八`。
